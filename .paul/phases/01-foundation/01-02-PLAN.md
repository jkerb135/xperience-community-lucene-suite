## Goal
A suite-owned search API (`ISuiteSearchService`) over `Kentico.Xperience.Lucene` that sees query text, facet filters, hit count and timing, with its Lucene logic proven by tests against a real in-memory index.

## Purpose
Kentico Lucene has no query hook, so rules (Phase 3), event capture (Phase 2) and the preview sandbox (Phase 5) all need one search entry point the suite controls. This is that entry point.

## Output
Search types + DI registration in the Suite project; a test project with one test file; an empty Suite Directory.Build.targets (closes the 01-01 isolation item).

<acceptance_criteria>

## AC-1: Text search ranks by configured field boosts
```gherkin
Given an index whose options configure fields Title (boost 3) and Content (boost 1)
And documents A (term only in Content) and B (term only in Title)
When the suite searches that term
Then B ranks above A, TotalHits = 2, and each hit carries its ItemGuid, score and stored fields
```

## AC-2: Paging and limits
```gherkin
Given 25 matching documents
When page 3 with page size 10 is requested
Then 5 hits are returned and TotalHits = 25
And requests with page size outside 1–100, page < 1, page × pageSize > 1000, query text > 256 characters, or more than 20 facet dimensions / 50 facet values are rejected with ArgumentException (ArgumentOutOfRangeException where a range applies)
And page = int.MaxValue with page size 2 is rejected (no integer overflow past the 1000 window) <!-- audit-added -->
And a null/empty IndexName, a null/empty facet dimension or value, or a facet value > 256 characters is rejected with ArgumentException <!-- audit-added -->
```

## AC-2b: Queries that analyze to nothing <!-- audit-added -->
```gherkin
Given StandardAnalyzer with English stop words
When the query text is only stop words or punctuation (e.g. "the", "!!!")
Then the search returns 0 hits and no exception (QueryBuilder returns null for such input)
```

## AC-3: Empty query browses
```gherkin
Given an index with documents
When the query text is null, empty or whitespace
Then all documents match (MatchAllDocsQuery) and facet counts cover the whole index
```

## AC-4: Facets count and filter
```gherkin
Given a faceted index (FacetsConfig + taxonomy) with dimension "Category" values Coffee(3) and Tea(2)
When searching with no facet filter
Then facet counts are Coffee 3, Tea 2
When filtering Category = [Coffee, Tea]
Then 5 hits match (values within one dimension are OR'd)
When filtering Category = [Coffee]
Then 3 hits match and the Category counts still show Tea 2 (drill-sideways)
```

## AC-5: Non-faceted indexes and bad data
```gherkin
Given an index whose strategy returns a null FacetsConfig
When searching
Then results return with an empty facet list and no taxonomy access is attempted
And a document with a missing or unparsable ItemGuid yields a hit with ItemGuid = null instead of an exception
And a request with facet filters against that index is rejected with ArgumentException instead of silently returning unfiltered results <!-- audit-added -->
```

    - `SuiteSearchResponse` record: Hits (IReadOnlyList&lt;SuiteSearchHit&gt;), TotalHits (int), Facets (IReadOnlyList&lt;SuiteFacet&gt;), Elapsed (TimeSpan). `SuiteSearchHit`: ItemGuid (Guid?), Score (float), Fields (IReadOnlyDictionary&lt;string, IReadOnlyList&lt;string&gt;&gt; of stored fields; multi-valued fields keep all values). `SuiteFacet`: Dimension + Values (label, count).

No configured fields for the index → throw InvalidOperationException naming the index and the options key to set. Sites replace it by registering their own ISearchQueryFactory.
    - `SuiteSearchOptions`: `Dictionary<string, Dictionary<string, float>> SearchFields` (index name → field → boost), case-insensitive index keys; `int FacetValuesPerDimension = 10`.
    - `ISuiteSearchService.Search(SuiteSearchRequest) → SuiteSearchResponse` (synchronous: the upstream searcher API is synchronous).
    Internal:
    - `SearchExecutor`: validates the request (limits in AC-2, using a long or division-based window check so page × pageSize cannot overflow — audit-added; facet filters on a FacetsConfig-less index → ArgumentException) before touching Lucene; empty/whitespace query → MatchAllDocsQuery, otherwise the factory's query; with a FacetsConfig: DrillDownQuery over the base query (one `Add(dim, value)` per value), `DrillSideways.Search(query, page*pageSize)`, facets via `GetAllDims(FacetValuesPerDimension)`; without: `searcher.Search(query, page*pageSize)`, empty facets. Slice the requested page from ScoreDocs; read stored fields; ItemGuid via Guid.TryParse of BaseDocumentProperties.ITEM_GUID (null on missing/invalid).
    - `SuiteSearchService`: ILuceneIndexManager.GetIndex(name) → null → ArgumentException; resolve the strategy via `serviceProvider.GetRequiredService(index.LuceneIndexingStrategyType)` as ILuceneIndexingStrategy — the same call upstream's DefaultLuceneSearchService makes, so an unregistered strategy fails loudly instead of being silently constructed (audit-changed from ActivatorUtilities) and call FacetsConfigFactory(); facets → UseSearcherWithDrillSideways, else UseSearcher; Stopwatch around the whole call sets Elapsed.
