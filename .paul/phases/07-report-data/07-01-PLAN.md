<objective>
## Goal
Add an internal `SearchReportService` that turns `LuceneSuite.SearchDaily` rollups into the numbers the Phase 8 report screens show, for one index and an inclusive UTC day range:
- **Overview:** totals and rates, plus the same totals for the previous period of equal length.
- **Trend:** one row per day in the range, including days with no searches.
- **Queries:** per query text, sortable by searches, no-result searches, lowest CTR or slowest (p95). Only surfaced queries are named; everything else is grouped as "(other)".
- **Latency:** overall p50/p95/p99 from the summed histogram.

User decision (2026-10-12): the overview compares with the previous period.

## Purpose
Core value: marketers measure search. Reports read rollups only, respect the surfacing threshold (k-anonymity) and never touch raw events.

## Output
- `Analytics/Reports/*`: service, models, percentile helper.
- DI registration (internal; the Admin project consumes it through the existing InternalsVisibleTo).
- Unit tests (pure math) and database tests on `comm_projects_test`.
- `docs/search-reports.md`: metric definitions.
</objective>

<acceptance_criteria>

## AC-1: Request validation
```gherkin
Given SearchReportService(IndexName, From, To) with From/To as UTC DateOnly, inclusive
Then a blank index, From > To, or a range longer than Retention.DailyRetention in days throws ArgumentException with a message naming the parameter
And the previous period is the equal-length range ending the day before From
<!-- audit-added -->
And To later than today (UTC) throws ArgumentException (future days would read as zero traffic)
And every result carries CompleteThrough = the rollup watermark (null when nothing has been rolled): days after it are not final, and Trend marks them IsComplete = false so Phase 8 can grey them out instead of showing a false drop
```

## AC-2: Overview
```gherkin
Given SearchDaily rows for the index (including "(other)" rows with QueryText NULL and browse rows with QueryText "")
When Overview is requested
Then totals are summed over every row in range (named, browse and (other)): Searches, ZeroResultSearches, SubmittedSearches, ClickedSearches, Clicks, Conversions, ConvertedSearches, SessionDays (sum of daily SessionCount, labelled as such)
And rates are computed as: NoResultRate = ZeroResultSearches / Searches, Ctr = ClickedSearches / Searches, ConversionRate = ConvertedSearches / Searches, AvgClickPosition = ClickPositionSum / Clicks; a zero denominator yields null (never NaN or a divide error)
And the same totals and rates are returned for the previous period, with a delta per metric that is null when the previous value is null or zero
<!-- audit-added -->
And the overview carries FirstDataDay (earliest SearchDaily day for the index); when the previous period starts before it, PreviousIsPartial = true and every delta is null (a half-covered previous period would show fake growth)
And rows of other indexes never count
```

## AC-3: Trend
```gherkin
When Trend is requested
Then it returns exactly one row per day from From to To, in order, with Searches, ZeroResultSearches, ClickedSearches and Ctr; days without rows have zeros and Ctr null
```

## AC-4: Query table with the surfacing threshold
```gherkin
Given surfacing = all retained history for the index: SUM(Searches) ≥ Surfacing.MinSearches AND distinct days ≥ Surfacing.MinDistinctDays (QueryText not NULL; browse "" counts like any text)
<!-- audit-added -->
And surfaced/not-surfaced is decided inside SQL in the same statement as the range aggregate (WhereIn / subquery on QueryText), so the database collation alone defines text equality on both sides — never by matching strings from two result sets in C#
When Queries(sort, skip, take) is requested
Then each surfaced query text with rows in range appears once with Searches, ZeroResultSearches, ClickedSearches, Clicks, Ctr, NoResultRate, AvgClickPosition and latency p50/p95
And all non-surfaced and NULL rows in range are summed into exactly one Other row (absent when empty), which is never sorted into or paged with the named rows
And sorts: Searches desc; ZeroResultSearches desc (only rows with > 0); LowestCtr asc (Ctr null last); Slowest p95 desc; ties broken by QueryText ordinal ascending
And take is 1–200 and skip ≥ 0 (else ArgumentException); TotalCount is the number of named rows before paging
And browse "" is flagged IsBrowse
```

## AC-5: Latency
```gherkin
Given the fixed histogram (bucket i upper bound DailyKpi.LatencyBucketUpperBoundsMs[i]; bucket 9 overflow)
Then a percentile p over summed buckets is the upper bound of the first bucket whose cumulative count ≥ ceil(p × total); in the overflow bucket it is reported as "over 5000 ms" (null ms value + IsOverflow); an empty histogram yields null
And Latency returns overall p50/p95/p99 and the summed bucket counts for the range
```

## AC-6: Efficient queries
```gherkin
Then each report section runs a bounded number of aggregate queries (no per-day or per-query round trips): overview ≤ 2, trend 1, queries ≤ 2 (range aggregate + surfaced set), latency 1
And all values reach SQL as parameters or typed WhereCondition values, never concatenated input (Having clauses use only validated ints and dates, as in AnalyticsRetention)
And an opt-in volume test (400 days × 500 queries/day) completes each section in < 1 s
```
