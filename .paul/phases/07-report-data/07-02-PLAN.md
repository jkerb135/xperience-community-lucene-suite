<objective>
## Goal
An opt-in test runner fills `LuceneSuite.SearchDaily` with realistic history so the Phase 8 report screens have something to show:
- It generates contract-faithful raw searches: as-you-type rows, paging, sessions, clicks with position bias, conversions, no-result typos, and log-normal latency.
- It rolls them with the real `RollupEngine` in memory, so the stored numbers are exactly what live traffic would produce.
- It writes only days that are empty **and** that the rollup job will never roll.
- A range-based clear removes the seeded days again.

The host (CommunityProjects, index DancingGoatSample) is then seeded with 60 days.

User decisions (2026-10-12):
- Opt-in test runner; nothing ships in a package.
- Vocabulary and clicked items come from the index, with a built-in list for the test DB.
- The host is seeded with about 60 removable days.

## Purpose
Reports, and later suggestions, can be designed and verified against months of plausible data without waiting for real traffic.

## Output
- `tests/.../Seeding/*`: the generator, the index vocabulary reader, the runner, and tests.
- A "Seeding demo history" section in `docs/search-reports.md`.
- The host seeded, with its range recorded in APPROVAL-CHECKS.
</objective>

<acceptance_criteria>

## AC-1: Contract-faithful generation through the real engine
```gherkin
Given a vocabulary, a day range, a daily volume and a random seed
When the generator runs
Then the raw rows follow the client contract:
  - one searchId per logical search, with sequences 1..n;
  - as-you-type prefixes within the text-change window, then the final text;
  - optional page 2 on the same searchId;
  - a session id on part of the searches;
  - clicks referencing a returned (sequence, position) within the attribution window, with positions biased to the top;
  - a few conversions;
  - no-result searches for typo/off-topic texts.
And each day is rolled with RollupEngine.Roll under RollupSettings.From(the configured options)
And the rolled Searches per day equal the generated logical searches started that day
And the same seed produces identical KPIs
<!-- audit-added -->
And a click position never exceeds the returned page nor the search's ResultCount; searches with 0 results get no clicks
And weekdays carry more traffic than weekends, and popular texts follow a long-tail (Zipf-like) distribution, so some queries surface and others stay below the threshold
```

## AC-2: Vocabulary from the index (or built-in)
```gherkin
Given LUCENESUITE_SEED_INDEXPATH points at a Kentico Lucene index folder
Then the newest generation subfolder that holds a valid index is opened read-only (no lock taken; the running host is unaffected)
And query texts come from the stored title field (default "Title", override LUCENESUITE_SEED_TITLEFIELD): whole titles lowercased, plus their significant words
And clicked ItemGuids are stored ItemGuid values of documents whose title contains the query text; ResultCount = the number of such documents (0 → a no-result search)
Given no index path
Then a built-in coffee-shop vocabulary with generated ItemGuids is used (the test DB has no index)
```

## AC-3: Safe target range, write and clear
```gherkin
Given LUCENESUITE_SEED_CONNECTIONSTRING (required; the runner skips otherwise), LUCENESUITE_SEED_INDEX (required) and LUCENESUITE_SEED_DAYS (default 60, 1–400)
Then the range ends on the day before the earliest of:
  - the first SearchDaily day of the index;
  - watermark + 1;
  - the earliest raw search day;
  - today (UTC).
And no SearchDaily row of the index may already exist in the range; the existence check and the insert run in one serializable transaction
<!-- audit-added -->
And the runner refuses unless LUCENESUITE_SEED_CONFIRM equals the target connection's database name (catalog), for seed and clear alike, so a stray env var or a full `dotnet test` run never writes to an unintended database
And the seeder holds the farm-wide rollup lock (RollupLock.TryAcquire on the target connection string, resource "LuceneSuite.Rollup") for the whole run and refuses when it is held; the range limits (watermark, earliest raw day, first daily day) are re-read inside the write transaction, so a concurrently starting rollup can neither roll a seeded day nor slip a real day into the range
And rows are written with SqlBulkCopy into LuceneSuite_SearchDaily. Kentico is not initialized against the target, so the running host sees no web-farm registration or cache side effects.
And the runner refuses when the installed Suite version is below 3, the table is missing, or the range would be empty
And the watermark, raw tables and other indexes are never touched
And LUCENESUITE_SEED_CLEAR=yyyy-MM-dd..yyyy-MM-dd deletes only that index's SearchDaily rows in that range (including "(other)" rows the retention fold created there) and reports the count
And the runner prints index, range, row count, random seed and the exact clear value
<!-- audit-added -->
And clear prints the per-day row counts it deleted
```

## AC-4: Reports work on seeded data
```gherkin
Given the test DB seeded with the built-in vocabulary for 60 days
When SearchReportService reads the range
Then Overview has non-zero Searches, CTR and no-result rate; Trend covers every day; Queries returns surfaced named rows and an Other row; Latency has p50 < p95
```

<task type="auto">
  <name>Task 1: Generator, vocabulary, writer</name>
  <files>tests/.../Seeding/SearchSeeder.cs, tests/.../Seeding/SeedVocabulary.cs, tests/.../Seeding/SearchSeederTests.cs</files>
  <action>
    **SeedVocabulary** (internal):
    - `FromIndex(path, titleField)` uses Lucene.NET `FSDirectory` + `DirectoryReader` on the newest `i-g*` generation folder where `DirectoryReader.IndexExists` holds. It reads stored title + `BaseDocumentProperties.ITEM_GUID` and skips deleted docs.
    - `BuiltIn()` provides about 40 coffee-shop titles with deterministic GUIDs.
    - Both expose `Match(text) → ItemGuids` (case-insensitive contains on titles) and the candidate texts: titles plus significant words of at least 4 characters, de-duplicated.

    **SearchSeeder** (internal, pure generation + separate writer):
    - `Generate(vocabulary, days, perWeekday, seed, settings)` returns raw rows. Rules:
      - Zipf weights over the texts; about 8 % typo texts (one letter dropped) and about 4 % off-topic texts, giving 0 results.
      - Typing prefixes 2–5 s apart (inside TextChangeWindow), then the final row; about 15 % submitted; about 10 % page 2.
      - About 40 % sessions.
      - CTR around 35 % for searches with results; click position weighted 1/position over the returned page.
      - About 3 % conversions, 5 min after the click.
      - Latency log-normal, median about 60 ms, tail over 1 s.
      - Weekend volume at 50 %.
      - Searches start between 00:10 and 23:00 UTC, so nothing crosses midnight; the attribution window stays within the day + 1 h.
    - `Roll` calls `RollupEngine.Roll` per day.
    - `SeedRange(conn, index, days)` computes the range per AC-3, reading the watermark (yyyy-MM-dd), MIN(ReceivedUtc) from LuceneSuite_SearchEvent and MIN(Day) for the index.
    - `Write(conn, kpis)` does a serializable check + SqlBulkCopy in one transaction; column mapping as in `DailyRollupStore.ToInfo`; empty QueryText stays '' (browse). No NULL rows are written (the fold creates those).
    - `Clear(conn, index, from, to)` is a parameterized DELETE.
    - All SQL is parameterized.
    - Audit-added:
      - Hold `RollupLock.TryAcquire(connectionString)` around range computation + write/clear.
      - Re-read the limits inside the serializable transaction.
      - Require `LUCENESUITE_SEED_CONFIRM` = `SqlConnectionStringBuilder.InitialCatalog`.
      - Clicks are bounded by min(ResultCount, page end); 0-result searches get no clicks.

    **Unit tests** (no DB):
    - Same seed → same KPIs.
    - Rolled Searches per day = generated logical searches.
    - No-result share between 5 % and 25 %.
    - Clicks never exceed the returned page.
    - Weekday volume > weekend volume.
    - At least one text crosses the surfacing threshold over 60 days and at least one stays below it.
    - The built-in vocabulary's Match is case-insensitive.
  </action>
