<objective>
## Goal
Every live search through `ISuiteSearchService` is recorded as one raw, identity-free event row in a Suite module class — with a page-memory `searchId`/sequence from the caller, a Suite session id for consented visitors, a scrubbed normalized query, result count, latency and submit flag — written in bulk off the request path.

## Purpose
Reports (v0.2), suggestions and A/B results all depend on accumulated history, so capture must start now. This plan is the ingest half of the agreed merge spec; merging into logical searches happens in 02-03's rollup.

## Output
Analytics module + raw event class/installer, request/response contract additions, scrubber, session cookie, capture decorator + bounded queue + bulk writer, unit tests, a dev-only xbk endpoint proving rows land in the database.
</objective>

## Agreed merge spec decisions (user "go", 2026-10-09)
1. Typo tolerance (client-side continuation): ≤1 edit at ≥4 chars, ≤2 edits at ≥8 chars, none under 4 (implemented by the client contract doc in 02-02; server stores what it receives)
2. Page / filter / sort changes never expire the 30 s window
3. Server re-checks only the 30 s rule (at rollup); trusts the client for the rest
4. Latency of a logical search = first row with the counted text
5. Contact activities only on submit and click (v0.2), carrying the same searchId
Consented visitors (cookie level ≥ Visitor): Suite session cookie, random, 30-min sliding, no contact link. Below Visitor: page-memory searchId only.

<acceptance_criteria>

## AC-1: One raw row per tracked search, off the request path
```gherkin
Given AddLuceneSuite registered and the analytics installer has run
When a live search executes through ISuiteSearchService
Then exactly one SearchEvent row is written (via IInfoProvider BulkInsert, in a background batch) with: SearchId, Sequence, SessionId (or null), ReceivedUtc, IndexName, normalized+scrubbed QueryText, Page, PageSize, FacetFilterCount, ResultCount, LatencyMs, IsSubmit, Origin (Client|Server)
And no column holds a contact id, IP, user agent, or hash
And the search response returns the SearchId used
```

## AC-2: searchId / sequence contract
```gherkin
Given a request carrying SearchId and Sequence
When it is captured
Then the row stores them unchanged
Given a request without SearchId (server-rendered, no JS)
When it is captured
Then the server mints a new SearchId, Sequence = 1, IsSubmit = true, Origin = Server
And a non-positive Sequence or an empty Guid is rejected by validation before search runs
```

## AC-3: Session id only at Visitor/All
```gherkin
Given the current Kentico cookie level is below Visitor
When a search is captured
Then SessionId is null and no Suite cookie is written
Given the cookie level is Visitor or All
When a search is captured
Then the Suite session cookie (registered with Kentico at Visitor level) is read or created with a random value, its expiry slides to now + 30 min, and the row stores it
And outside an HTTP request (e.g. background code) SessionId is null without error
And when the response has already started (Response.HasStarted) the cookie is not written, the existing cookie value (if any) is still used, and no exception occurs <!-- audit-added -->
And cookie-level / request-scoped services are resolved per call from the current request, never captured by a singleton <!-- audit-added -->
```

## AC-4: PII scrub and normalization
```gherkin
Given query text with an email, a phone/order number (≥7 digits, separators allowed), mixed case, repeated whitespace, or > 256 chars
When normalized
Then emails become "{email}", digit runs become "{number}", text is trimmed, whitespace collapsed, lower-cased invariantly, capped at 256
And ordinary text with ≤6-digit numbers (e.g. "iphone 15", "2025 calendar") is unchanged apart from case/whitespace
```

## AC-5: Exclusions
```gherkin
Given a request with TrackAnalytics = false (admin query tester, previews, count probes)
Or a request whose User-Agent matches the bot list
Or a search against an index with zero documents (rebuild in progress, upstream #173)
Or a browser prefetch/prerender request (`Sec-Purpose: prefetch` or `Purpose: prefetch`) <!-- audit-added -->
When it executes
Then results are returned normally and no event is enqueued
And the admin query tester always sends TrackAnalytics = false
```

## AC-6: Never slows or breaks search
```gherkin
Given the bounded queue is full or the database write fails
When more searches execute
Then they return normally; overflowed events are dropped and counted; a failed batch is logged once (rate-limited) and discarded
And capture adds no synchronous database call to the search path
And any exception thrown by capture itself (scrubber, cookie, enqueue) is caught, logged rate-limited, and never reaches the caller or alters the search result <!-- audit-added -->
And a value exceeding a column length can never fail a whole batch: every field is length-checked/truncated before BulkInsert <!-- audit-added -->
```

## AC-7: Module class hygiene
```gherkin
Given the analytics installer
When the app starts on a fresh database, and again on an already-installed one
Then the Suite resource and SearchEvent class exist exactly once (idempotent), with an explicit installer version for future migrations
And two instances starting at the same moment (web farm) cannot create duplicates or fail startup — creation is serialized (e.g. sp_getapplock via Kentico's connection, or create-then-catch-duplicate-and-reread) and proven by a test that runs the installer concurrently <!-- audit-added -->
And the class's TypeInfo has continuous integration disabled, no event/staging logging, and no object caching
And the class name/prefix (lucenesuite.*) does not collide with XpSearch's xpsearch.* types
```

## AC-8: End to end in xbk
```gherkin
Given xbk running with a dev-only demo endpoint that calls ISuiteSearchService
When it is called with and without searchId/sequence, with a bot User-Agent, and with an email in the query
Then the database shows the expected rows (scrubbed text, minted id for the no-id call, no row for the bot call) within the flush interval
And Suite build 0 warnings/0 errors, all tests pass, xbk scratch builds 0 errors / ≤ 279 warnings (normal + SeparatedAdmin)
```
