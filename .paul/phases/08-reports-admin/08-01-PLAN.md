<objective>
## Goal
Add a "Search reports" page to each index's Search tuning section. It shows, for a chosen UTC date range:
- six KPI tiles with the change against the previous period;
- a daily trend chart of searches and no-result searches, with a table view;
- latency p50/p95/p99 and the histogram.

The page recomputes whenever the range changes.

User decisions (2026-10-12):
- The trend is a token-styled SVG chart with a "Show as table" switch; no amCharts.
- The range offers presets plus a custom range.
- Phase 8 is two plans. This plan builds the page, range bar, KPIs, trend and latency. 08-02 builds the query tables and the row actions (query tester, create rule, add synonym).

## Purpose
This is the first marketer-facing measurement screen ("measure search without a developer"). It reads only rollups through `SearchReportService` (07-01).

## Output
- `SearchReportsPage` (C#), with one VIEW-gated command.
- `reports/*` client template, with pure helpers tested in node.
- Registration and DB tests.
- An APPROVAL-CHECKS entry for the visual review.
</objective>

## Screen design (from /xbyk-admin-ui:design-screen, PLAN 2026-10-12)

**Classification:** a report dashboard inside the existing Site Search section layout (Kentico renders the section menu). No kit template fits and npm exports no templates, so the screen is composed from `Stack`, `Row`, `Column` and `Card`, like the query tester.

```
[Headline h2 "Search reports" + index name]
[Range bar (Paper/Card row)]
  NameToggleButtons: 7 days | 30 days | 90 days | 12 months | Custom
  DateTimeRangeInput (dates only; shown for Custom; min = today − DailyRetention + 1, max = today)
  TextWithLabel "Compared with" <previous range>
[Callouts (onDesk, as applicable)]
  Info: "Days after <CompleteThrough> are not final yet" (or "No day has been rolled up yet")
  Info: "No comparison: the previous period starts before the first data (<FirstDataDay>)"
[KPI row: InfoCard × 6 in Row/Column (colsMd 4 → 3 per row; narrow: 6 → 2 per row)]
  Searches · No-result rate · CTR · Conversion rate · Avg click position · Session-days
  text = formatted value ("—" when null); details = delta line ("+15 % vs previous period" / "No comparison"); tooltip = metric definition (from docs/search-reports.md)
[Card "Searches per day"]
  Switch "Show as table"
  TrendChart (custom SVG, tokens only) | Table (Day, Searches, No results, CTR, Final?)
[Card "Latency"]
  TextWithLabel × 3: p50 / p95 / p99 ("≤ 100 ms" or "over 5 s")
  Histogram: same SVG bar component (10 buckets, labels ≤10 ms … >5 s) + table view via the same switch
States: Spinner while loading (range bar stays usable); NotificationBarAlert for a command error; empty state (Card body text) when the range has no searches.
Audit-added: a rejected command (server failure, network) also lands in the NotificationBarAlert with the last good result kept on screen; never an unhandled promise.
```

**Component map (npm 31.9.1; confirmed in dist/entry.d.ts at PLAN):**
- Exported and used: `InfoCard` (caption/tooltip/text/details, strings only), `NameToggleButtons` (selectedItemId/items/onChange), `DateTimeRangeInput` (value/onChange/minDate/maxDate), `Table`, `Card`, `Headline`, `TextWithLabel`, `Switch`, `Callout`, `NotificationBarAlert`, `Spinner`, `Row`/`Column`/`Stack`.
- Not exported (not used): `ColumnChart` (amCharts 5, not externalized → own unlicensed bundle), `OverviewCard`, `ToggleButtons` base, templates.
- Chart: custom `TrendChart` SVG with `var(--color-*)`, `var(--spacing-*)` and `var(--font-size-*)` tokens only.
  - `role="img"` with an `aria-label` summary (range, total, peak day).
  - Incomplete days differ by pattern/opacity **and** a legend entry, never by colour alone.
  - The y-axis has 3–5 nice ticks.
  - The table view is the accessible equivalent and is reachable by keyboard.
- Headings: real `<h2>`/`<h3>` inside `Headline`/`Card` headlines (Headline renders a div).
- One primary action: none needed (the page recomputes on change; no Save). Refresh = re-select the preset; no extra button.
</design>

<acceptance_criteria>

## AC-1: Page, permissions and command
```gherkin
Given a user with Site Search → View
When they open Site Search → <index> → Search reports (slug "reports", order 50, icon Graph-like icon verified in the kit's public/icons)
Then the page loads with ValidatePage = SearchTuningSectionPage.Validate (unknown index → Kentico's not-found handling)
And one [PageCommand(Permission = VIEW)] Report(from, to) returns Overview + Trend + Latency for the page's index in one response; the index name always comes from the page, never the client
And an ArgumentException from the service (From > To, To > today, range > DailyRetention) comes back as Error text, not a server error
And a user without View cannot open the page or run the command (registration test asserts the attribute + permission; Kentico enforces)
And client properties carry Today (UTC, server clock) and MaxDays (DailyRetention in days) so the range bar never offers a range the service rejects
```

## AC-2: Range bar
```gherkin
Given the page opens
Then the default range is the last 30 complete days ending yesterday (UTC), and the "Compared with" text shows the previous period
When a preset is chosen (7 / 30 / 90 days, 12 months = 365 days, all ending yesterday; capped at MaxDays)
Or a custom range is picked (dates only, min Today − MaxDays + 1, max Today)
Then the report recomputes, the latest request wins (an earlier response arriving later is ignored), and the range bar stays usable while loading
And the selected range survives a reload through the URL query string (from/to), invalid values falling back to the default
<!-- audit-added -->
And report days are UTC calendar dates handled as plain yyyy-MM-dd strings end to end: a date picked in DateTimeRangeInput converts with the picked value's local calendar fields (getFullYear/getMonth/getDate), never toISOString; yyyy-MM-dd strings are never parsed with the Date constructor for display; the range bar says the days are UTC (picking 1 October in UTC+2 or UTC−5 requests 2026-10-01, not the day before)
And if writing from/to to the URL interferes with the admin's router (route reload, broken Back), URL persistence is dropped rather than worked around, and recorded as a deviation
```

## AC-3: KPI tiles and notices
```gherkin
Given a report result
Then six InfoCards show:
  - Searches;
  - No-result rate;
  - CTR;
  - Conversion rate;
  - Avg click position;
  - Session-days.
And numbers use the browser locale and rates show as percentages with one decimal; a null value shows "—"
And details show the delta for counts as a signed relative percentage ("+15.0 % vs previous period"), "No previous data" when the delta is null with a previous value of 0/null, or "No comparison" for every tile when PreviousIsPartial
<!-- audit-added -->
And rate tiles (No-result rate, CTR, Conversion rate) show the change in percentage points computed from Current and Previous ("+3.0 pp"), and Avg click position shows the absolute change in positions ("−0.4"); a relative change of a rate is never shown (30 % → 33 % must not read "+10 %")
And a Callout explains PreviousIsPartial (with FirstDataDay) and one explains days after CompleteThrough (or that nothing has been rolled up yet)
And a range with zero searches shows an empty state instead of tiles full of dashes
```

## AC-4: Trend chart with table view
```gherkin
Given Trend days
Then the SVG chart shows one column per day for Searches with No-result searches overlaid. Days with IsComplete = false use a distinct pattern and appear in the legend as "Not final yet".
And the chart has role="img" and an aria-label summary; "Show as table" switches to a Table (Day, Searches, No results, CTR, Final) with the same data
And with 365 days the chart stays readable: bars thin to fit, the x-axis labels at most ~8 dates, and nothing overflows at ~790 px content width
```

## AC-5: Latency
```gherkin
Given Latency
Then p50/p95/p99 show as "≤ N ms" or "over 5 s", and "—" for an empty histogram
And the 10-bucket histogram uses the same chart component with labels ≤ 10 ms … ≤ 5 s, > 5 s, plus the table view
```

## AC-6: Design validation
```gherkin
Given the host running with the admin client (Proxy 3011) and the seeded DancingGoatSample history
Then in the browser pane at ~790 px and 1440 px content width:
  - only kit tokens are used (no literal colours or sizes);
  - focus moves visibly through the toggle → range input → switch → table;
  - headings are real heading elements;
  - loading, error and empty states render.
And screenshots plus findings are recorded in an APPROVAL-CHECKS entry (Pending, reviewed at milestone end)
```
