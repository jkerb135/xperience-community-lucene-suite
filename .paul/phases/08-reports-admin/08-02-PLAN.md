<objective>
## Goal
Add the query table to the Search reports page:
- surfaced queries for the selected range, switchable between Top, No results, Lowest CTR and Slowest;
- 25 rows per page;
- the "(other)" total below the table.

Each row gets three actions. Each opens its target with the query already filled in:
- **Open in query tester:** the query runs on arrival.
- **Create rule:** a "Query is <text>" condition.
- **Add synonym:** the query as the first term.

User decisions (2026-10-12):
- The prefill travels as a one-time sessionStorage handoff (no URL query strings, no server state).
- One table with a sort switch.
- Actions the user lacks permission for are shown disabled with a tooltip.

## Purpose
This closes the measure → act loop: a marketer sees a no-result query and fixes it with a rule or synonym in two clicks, without a developer.

## Output
- Page command + DTOs.
- `QueryTable` + `handoff` client modules.
- Prefill hooks in the three existing editors.
- Tests.
- APPROVAL-CHECKS #6.
</objective>

<acceptance_criteria>

## AC-1: Queries command
```gherkin
Given the reports page of an index
When the client calls [PageCommand(Permission = VIEW)] Queries(from, to, sort, page)
Then it returns 25 rows of SearchReportService.Queries for the page's index (skip = (page − 1) × 25) with QueryText, IsBrowse, Searches, ZeroResultSearches, ClickedSearches, Ctr, NoResultRate, AvgClickPosition, LatencyP50, LatencyP95; plus Other (or null) and TotalCount
And an invalid range, unknown sort or page < 1 returns Error (never a server error); a page beyond the last returns an empty Rows with the true TotalCount
And client properties add CanManageRules / CanManageSynonyms (IUIPermissionEvaluator, as RuleListingPage does) and admin-root-relative paths for the query tester, Create rule and Create synonym pages of this index (IPageLinkGenerator with the section parameter)
```

## AC-2: Query table
```gherkin
Given a report range
Then the Queries card shows the surfaced queries for the chosen sort with paging, recomputed when the range, sort or page changes (latest request wins; page resets to 1 on range or sort change)
And the browse row reads "(browse – no query text)", and the (other) total shows under the table with an explanation tooltip
And numbers and rates use the 08-01 formatters; p95 uses the percentile label
<!-- audit-added -->
And the chosen range, sort and page survive the round trip to a target page and back: they are kept per index in sessionStorage ("lucene-suite:reports:{index}") and restored on load when still allowed (isAllowed), else the default; never in the URL
And only surfaced text ever appears (the service guarantees it; the UI adds no other source of query text)
```

## AC-3: Row actions and handoff
```gherkin
Given a row with query text q on index i
When "Open in query tester" is chosen
Then a handoff {target: "queryTester", index: i, query: q, expires: now + 2 min} is written to sessionStorage and the browser goes to the query tester of i, which takes the handoff once, fills the query box and runs the search
When "Create rule" is chosen (enabled only with Manage rules and a non-browse row)
Then Create rule opens with one condition "Is" + q already in the conditions editor (the rule name stays for the marketer to type)
When "Add synonym" is chosen (enabled only with Manage synonyms and a non-browse row)
Then Create synonym opens with q as the first term
And a handoff is used at most once, only by its target, only on the same index, only before it expires, and only when the target form is empty (an existing rule's or synonym's values are never overwritten)
<!-- audit-added -->
And the handoff is bound to the exact target page path (the admin-root-relative Create rule / Create synonym / query tester path from the client properties): a consumer takes it only when location.pathname ends with that path, so a pending handoff can never land in an existing rule's or synonym's edit page, even one whose conditions or terms are empty
And texts containing the scrubber placeholders {email} or {number} (analytics replaced the real value) disable Create rule and Add synonym with the title "Contains a removed value; a rule or synonym would never match"; the server flags them (HasPlaceholder via QueryScrubber's constants), never the client
And the query tester's prefilled search runs through its normal untracked path (TrackAnalytics = false), so following a report link never adds analytics rows
And when sessionStorage is unavailable or contains garbage, nothing breaks: the action still navigates and the target opens empty
And disabled actions carry a title naming the missing permission
```

  - the editors of existing rules and synonyms are untouched;
