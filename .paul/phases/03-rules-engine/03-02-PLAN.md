<acceptance_criteria>

## AC-1: Facet selection can never get stuck (H1)
```gherkin
Given values are ticked in one or more facet dimensions
When a search returns facets that omit a ticked value (outside top-N, zero hits, or an error)
Then every ticked value is still shown and untickable (with count 0 when missing)
And an applied-filters bar ("Applied filters:" + one removable Tag per value + "Clear all" Button), built from exported npm components following the kit's FilterStatusIndicator pattern, shows all selections and clearing works
```

## AC-2: Request handling (H2)
```gherkin
Given a search is in flight
When the user changes the query, a facet, or the page
Then the previous request is aborted (executeCommand AbortController), only the latest response is applied, and facets/pager/search are disabled or marked in progress while it runs
And when executeCommand returns undefined or throws, the previous results stay and a warning Callout says the search failed
And rejected input shows only the inline Callout (the server-side AddErrorMessage snackbar is removed)
```

## AC-3: Layout at laptop widths
```gherkin
Given content widths of ~790 px and 1440 px
Then the results table (or its loading skeleton) is visible in the first screen without scrolling at both widths
And the search field follows the kit SearchInput pattern (magnifier, Enter submits) with the explanation text below it (explanationText, not placeholder), and never clips or wraps awkwardly
And long facet dimensions show the first 5 returned values with a "Show more"/"Show less" toggle revealing the rest of what the server returned (up to FacetValuesPerDimension; values beyond the server cap stay unreachable — recorded in KNOWN-LIMITATIONS) (audit-clarified); facet headings are humanized (e.g. "CoffeeProcessing" → "Coffee processing")
And stats (total hits, elapsed) are separated from the facets by kit spacing
And the redundant overflowX wrapper is removed (the npm Table scrolls itself)
```

## AC-4: Kit states and detail view
```gherkin
Given a search is loading → the npm Table shows its built-in skeleton (rows = undefined)
Given zero hits → a QuickTip Callout with a "Clear filters" action (when filters are applied)
Given a row is clicked → its stored fields open in the exported SidePanel (focus moves into it, Escape/close returns focus to the row), values rendered as plain text
```

## AC-5: Accessibility and polish
```gherkin
Then the page title and facet group titles are exposed as headings (role="heading" + aria-level wrappers, since kit Headline renders a div)
And the page title no longer repeats the index name shown in the breadcrumb
And the first table column is the display title (ItemGuid moves to the detail panel / last column)
And the C# side: app name "Site search" (sentence case), Icons.Magnifier, an icon on the Query tester menu item, an empty-listing Callout on the Site Search index listing, and the Entries column no longer located by caption text
```

## AC-6: Tests and design validation are in place
```gherkin
Given the client state logic (selection merge with returned facets, latest-request-wins, humanized headings) lives in small pure functions
Then they are unit-tested with node --test (no new test framework), and `npm run typecheck` passes
And .paul/SPECIAL-FLOWS.md lists design validation against the kit as REQUIRED for any admin UI work (component exports checked, tokens only, kit states, visual check at ~790 px and 1440 px)
And Release build 0/0, all .NET tests pass, locked-mode restore passes, xbk scratch builds 0 errors / ≤ 279 warnings (both modes)
```
