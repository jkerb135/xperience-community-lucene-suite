# Phase 13 Plan 02.1: Save-Conflict Quick Fix Summary

**Marketers can save the same rule or synonym as often as they like.** Only a real concurrent edit is refused, and on rules it offers a Reload that asks before discarding edits.

## Acceptance Criteria Results

| Criterion | Status | Notes |
|-----------|--------|-------|
| AC-1: No false conflict | Pass | Host: 3 saves in a row on a rule and on a synonym; toast survives; DB holds the last change |
| AC-2: Real conflicts still caught | Pass | Host: SQL LastModified bump → two refusals in a row on both pages, nothing stored |
| AC-3: Reload on a rule conflict | Pass | Alert + "Reload the rule" in a polite region; Dialog confirm; Cancel keeps edits and returns focus; confirm reloads and clears the alert |
| AC-4: Nothing else changes | Pass | Rule 4 unedited save byte-identical; create pages unchanged; gates unchanged |

## Verification Results

- Build Debug + Release: 0 warnings.
- .NET: 836–837 passed, 6 skipped. The only failure was the known RulesOverhead timing flake, which passed alone.
- Client 92/92; tsc clean.
- Host evidence is in APPROVAL-CHECKS #17. Test data was removed and the counts are back to baseline.

## Deviations from Plan

| Type | Count | Impact |
|------|-------|--------|
| Approach changed (user decision) | 1 | The planned token refresh in the returned form items cannot work: Kentico 31.9.1 ignores returned values after a successful save (proven by request capture and a debug render probe). Successful edit saves now NavigateTo the same page instead |
| Extra root cause | 1 | A just-saved Info holds LastModified as local-kind time, which formats with an offset; tokens now come from the DB-read row |
| Plan premise corrected | 1 | Kentico form items are flat (categories are siblings), so no nested lookup was needed |
| Removed | 1 | The FormItemsExtensions helper was deleted after the approach change |

## Lessons

- The round-1 DB tests passed while the feature failed on the host: they covered the server half of a client round-trip. The host check caught it.
- On success, Kentico's admin client doesn't apply returned values; on failure it does. Use NavigateTo or a component command to refresh server-owned state after a success.
