<objective>
## Goal
Bring the query tester to the handoff (Screen 2) with the 13-03 patterns.
- **Summary strip:** totals and elapsed time, fired-rule chips (icon + name + action summary), synonym tags.
- **Results table:** position, "Pinned #n" tag, score DataBar, monospace GUID, and a range footer with rows per page.
- **Compare:** each column becomes a table with a Moved column (arrows, "—", "New").
- **Error state:** a "Try again" action.

## Purpose
The query tester is where marketers check what tuning does. Today the summary is scattered headings, scores are bare numbers, and rank movement is plain text beside list items. The handoff makes the effect of rules and synonyms readable at a glance.

## Output
- Client changes in the query tester (template, CompareView, helpers + node tests).
- `RangeFooter` gains a page limit.
- The fired-rule payload gains an action summary.
- One DB/unit test.
- APPROVAL-CHECKS entry.
</objective>

## AC-1: Result summary strip
```gherkin
Given a successful search (not Compare)
Then one Paper (subtle elevation, radius M, padding 16px 24px, items 16px apart) shows:
  line 1: "Total hits" and "Elapsed" TextWithLabels 40px apart
  line 2 (when Apply rules is on and rules did not fail): heading "Fired rules (n)" and one chip per fired rule — a link with 1px border, 8px radius, 4px 10px padding, product-hover text: icon (xp-pin if it pins, else xp-arrow-up if it boosts, else xp-eye-slash if it hides, else xp-database) + bold name + " · {action summary}" (e.g. "2 pins, 1 boost"), linking to the rule's edit page; a deleted rule shows "{label} (deleted)" without a link; a rule's custom data stays readable below the chips as today
  line 3 (when Apply synonyms is on, synonyms did not fail and the query is not empty): "Synonyms applied (n)" with each synonym as a Tag that opens its edit page (deleted → plain text)
And "No rules fired for this search." / "No synonyms applied to this search." stay as today
And the headings keep their programmatic levels (h2)
And chip icons are aria-hidden, so each chip's accessible name is its visible text ("{name} · {summary}"), and chips are reachable and activatable by keyboard <!-- audit-added -->
```

## AC-2: Results table
```gherkin
Given results on page p with page size s
Then the table columns are: # (position (p−1)·s + i + 1), the first key field as Title with a "Pinned #n" Tag (selected background) before it when pinned (the separate Pinned column goes), the other shown key fields, Score (DataBar, ratio = score / top score on this page, label at 4 decimals, info tone from a runtime token; a non-finite or non-positive top or score gives an empty bar, never NaN width <!-- audit-added -->), Item GUID (12px monospace, low-emphasis)
And rows stay one line (50 px), clicking a row opens the details SidePanel and closing it returns focus as today
And positions, the range text and the selected page/size always describe the rows on screen: page and page size are committed together with the result of a successful search (as `page` is today), never when the request is sent, so a failed or superseded request cannot shift # or the footer <!-- audit-added -->
And under the table a RangeFooter shows "{from}–{to} of {total} documents", a Rows per page Select (10, 25, 50; default the server's page size) and Pagination; changing the size searches page 1 with that size; pages beyond the result window are not offered (the total text still shows the real total)
```

## AC-3: Compare rank movement
```gherkin
Given Compare is on
Then Baseline and Tuned keep their own Apply rules / Apply synonyms switches and context pickers (user decision: keep the configurable columns, restyle)
And an explainer says each column runs the same query with its own settings and arrows show how far Tuned moved each document compared with Baseline
And Baseline lists results as a table # / Title / Score (DataBar), Tuned as # / Title / Moved
And Moved shows xp-arrow-up + n in success colour or xp-arrow-down + n in alert colour (600 weight, hidden text "{n} places up/down"), "—" when unchanged, and a "New" Tag when the document is not in Baseline's list
And "Not in this column (n)", fired-rule/synonym lines (as chips/tags like AC-1), row → details panel with focus return, and per-column failure alerts behave as today
```

## AC-4: States
```gherkin
Given a search is running
Then a Spinner shows in place of the table (Phase 13 deviation: no skeletons) and the summary keeps the last values
And while previous rows stay visible during a search, the results region carries aria-busy="true" until the answer arrives <!-- audit-added -->
Given a search fails (request error)
Then the "Search failed" Callout ("The previous results are still shown. Try again.") gets a secondary "Try again" action that re-runs the last submitted search (same query, page, size, filters, switches) through the latest-request-wins path and is disabled while it runs
And Try again is offered only for a failed request, not for "Search rejected" (a validation error, where retrying the same input cannot succeed) <!-- audit-added -->
And the previous results stay on screen with their score bars faded (Stale context), text at full contrast
Given no documents match
Then the existing "No documents match" Callout (with Clear filters when filters are applied) shows, never while loading or failed
```
