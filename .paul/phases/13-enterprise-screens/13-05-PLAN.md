## Goal
Close the two v0.2 review follow-ups before `/paul:complete-milestone`:
1. **(#12)** Every create, update and delete of a rule, synonym or blocked suggestion writes one Kentico event-log entry saying who changed what. Bulk rule actions keep their single summary entry instead of one per rule.

## AC-1: Audit trail for single changes
```gherkin
Given a rule, synonym or blocked suggestion is created, updated or deleted through the admin, the report's Block action or the Info providers
Then exactly one Kentico event-log entry is written per change, Information level, source "LuceneSuite", code {RULE|SYNONYM|BLOCKED_SUGGESTION}_{CREATE|UPDATE|DELETE}
And its description names the index, the object id and its display text (rule name; synonym terms as stored; blocked text and match mode)
And the entry records the acting admin user (verified on the host in CMS_EventLog; if Kentico does not fill it from the request, the handler sets it explicitly)
And a failure while logging never fails or rolls back the user's save or delete (logged as an exception, swallowed)
And the description is one line, capped at 1,000 characters (long synonym term lists are truncated with "…"), and never contains rule JSON <!-- audit-added -->
And a change made without an authenticated user (API, background code) is still logged, with no user, and never fails <!-- audit-added -->
```

## AC-2: Bulk actions stay one entry
```gherkin
Given a rules bulk action (enable, disable, priority, delete) over n rules
Then per-item change-log entries are suppressed (CMSActionContext with LogEvents = false around the bulk writes) and the existing RULES_BULK_* summary entry is unchanged
And any other code running with Kentico's LogEvents = false (installers, seed runner, tests) writes no change-log entries
```

## AC-3: Local-time validity labels
```gherkin
Given the rule create or edit form
Then the fields read "Valid from" / "Valid until" (no "(UTC)") with help text saying the time is in your local time and that the status line shows the result in UTC, keeping "Leave empty to start immediately." / "Leave empty to run indefinitely."
And stored values and the status line are unchanged; the rules listing keeps "(UTC)" (it shows stored UTC values)
And the docs (rules-and-synonyms.md validity rows) say the same
```

## AC-4: Records corrected
```gherkin
Then KNOWN-LIMITATIONS no longer claims the Kentico event log records rule or synonym changes without this handler (lines ~286, ~328), the blocklist "no audit trail" entry is updated to the new behaviour (keeping the 1000-row CMSLogSize note), and a new entry records that disabled report row actions give sighted keyboard users no reason (screen-reader text exists; upgrade path: focusable aria-disabled actions with a reason on focus)
And docs mention the audit trail where they describe rule/synonym/blocklist management
And docs and KNOWN-LIMITATIONS state plainly that the trail lives in Kentico's event log, so how long it is kept follows the site's event-log size setting (CMSLogSize; the host keeps 1,000 rows, about two days), and that sites needing a longer audit history must raise that setting <!-- audit-added -->
```
