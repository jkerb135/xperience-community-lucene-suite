## Goal
Screen 4 of `project-sidecar/design/design_handoff_lucene_suite_enterprise/README.md`, kept on the native ModelEditPage (user decision 2026-10-12: no sticky save bar; Kentico's Save and unsaved-changes prompt stay):
- **Sections:** General / Conditions / Actions / Custom data as native form categories, with the handoff's copy (explanations, "Enter a name.", subtexts).
- **Live status:** Active / Scheduled / Expired / Disabled shown at the top of the form, updating as Enabled and the dates change (same rule as the 13-01 listing).
- **Condition editor (user request):**
  - each context row chooses a contact group by display name or "Custom context…" (stored as the bare code name — the shipped Widgets resolver passes bare code names);
  - each facet row chooses the dimension and value from the index (values with counts) or "Other value…".
- **Layouts per the handoff:** condition boxes (border, radius 8, padding 16, "Condition n" + quinary bin), top-aligned Query/Text grid, facet rows `5fr 5fr auto`, boosts `4fr 4fr 2fr auto`, pin rows (xp-pin, title, type Tag, 96 px position, remove), hides as removable Tags.

## Purpose
User: the old rule builder's condition editor "was more seamless"; the handoff makes the edit page match the enterprise screens. Behaviour and stored JSON stay unchanged.

## Output
- Server: form categories + copy in RuleEditModel; `FacetValues` and `ContactGroups` commands on the conditions component; shared `ContactGroupAccess` (extracted from QueryTesterPage); display-only `RuleStatus` form component
- Client: reworked conditions/boosts/pins/hides components, new RuleStatusFormComponent, pure helpers + node tests
</objective>

## Design (from /xbyk-admin-ui:design-screen, PLAN run 2026-10-12)
- **Classification:** edit form → native ModelEditPage (enterprise.md §2). Custom components render inside its Paper and never add a 24 px heading; sub-blocks ("Condition 1") are `Headline S`, level 3.
- **Native capabilities checked (31.9.1 Admin.Base XML):** `FormCategoryAttribute` exists → sections. No native switch/toggle form component → Enabled stays a CheckBox. Native forms lay fields out one per row → Priority/Enabled and Valid from/until stay stacked (no side-by-side). No page-level status slot on ModelEditPage → status is a display-only custom form component at Order 0.
- **Region outline (inside the native edit template):**
  ```
  [native header: rule name / "Create rule", Save]
  RuleStatus (display only): Icon + text "Active · fires on matching searches" / "Scheduled · starts {from} UTC" / "Expired · ended {until} UTC" / "Disabled"
  Category "General": Name ("Enter a name."), Description, Enabled, Priority ("Lower numbers run first."), Valid from (UTC) ("Leave empty to start immediately."), Valid until (UTC) ("Leave empty to run indefinitely.")
  Category "Conditions": Callout "How conditions match" (unchanged copy)
     condition box × n: Headline S level 3 "Condition n" + quinary xp-bin
        grid minmax(0,1fr) minmax(0,2fr), align-items start: Select Query · Input Text
        facet rows grid 5fr 5fr auto: Select Facet · Select Value (MenuItem primaryLabel value, secondaryLabel count; "Other value…" → Input) · remove
        context rows: Select Visitor context (groups by display name, secondaryLabel "Contact group"; "Custom context…" → Input) · remove
        Add facet · Add context (secondary)
     Add condition (secondary)
  Category "Actions" (subtext "What happens to the results when the rule fires."): Boosts grid 4fr 4fr 2fr auto + Add boost · Pins rows (xp-pin, title, type Tag, 96 px position Input, remove) + "Pin items" (existing ItemPicker) · Respect-filters checkbox · Hides: removable Tag per item + "Hide items"
  Category "Custom data" (subtext "Returned with the search results when the rule fires, for example to show a banner."): TextArea 4 rows
  ```
- **Stale values:** a stored facet dimension/value the index no longer reports stays selected with secondaryLabel "not in the index"; a stored context that is no contact group shows as a custom context (by design a custom string equal to a group code name *is* that group).
- **No contact-group permission:** users without Contact groups → View see only "Custom context…" plus their stored values; the explanation says "You need Contact groups access to pick groups."
- **States:** FacetValues/ContactGroups loading → value/context Selects disabled with explanation "Loading…"; error or non-faceted index → free-text Inputs (today's behaviour) + one NotificationBarAlert at the top of the Conditions component.
- **Focus:** choosing "Other value…" / "Custom context…" focuses the revealed Input; add/remove focus rules unchanged from 03-06.
- **Tokens:** borders/radii via runtime-verified tokens and `BorderRadius`/`Spacing` enums; no hex.

<acceptance_criteria>

## AC-1: Sections and copy match the handoff
```gherkin
Given the rule edit or create page
Then fields are grouped into General, Conditions, Actions and Custom data sections in that order
And Name shows "Enter a name." only after blur or a failed save
And Priority, Valid from and Valid until show the handoff explanations
And Custom data is a 4-row text area that still rejects invalid JSON on save
```

## AC-2: Live status
```gherkin
Given an enabled rule with Valid from tomorrow
Then the status reads Scheduled
When the marketer clears Valid from (without saving)
Then the status reads Active
And unticking Enabled shows Disabled; a past Valid until shows Expired
And the status agrees with the 13-01 listing for the same saved rule
```

## AC-3: Contexts from contact groups
```gherkin
Given contact groups "VIP customers" (VIPs) and a recipient list "Newsletter"
And the user has Contact groups → View
When the marketer adds a context
Then the Select lists "VIP customers" (not "Newsletter") and "Custom context…"
And choosing "VIP customers" stores "VIPs"; reopening shows "VIP customers"
And a stored "mobile" shows as Custom context "mobile"
And without Contact groups → View the command returns no groups and only custom contexts are offered
```

## AC-4: Facets from the index
```gherkin
Given a faceted index with dimension ContentType holding Article (12) and Cafe (3)
When the marketer adds a facet
Then Facet lists the index's dimensions and Value lists Article and Cafe with counts
And "Other value…" accepts a typed value
And a stored value the index no longer reports stays selected, labelled "not in the index"
And a non-faceted index or a failed FacetValues call falls back to free-text inputs with an error bar (failure only)
```

## AC-5: Nothing else changes
```gherkin
Given any existing rule
When it is opened and saved without edits
Then the stored Conditions/Actions/UserData JSON is byte-identical
And server error paths (conditions[i].…, boosts[i].…) still land on the right control
And Manage-rules gating, read-only View mode, concurrency (LoadedVersion) and pins/hides behaviour are unchanged
```

## AC-6: Trust boundary
```gherkin
Then FacetValues and ContactGroups take the index and user from the server (GetFormItems / user accessor), never from the client
And FacetValues runs with rules off and analytics off
And both commands fail closed: an error message, never an exception or another index's data
```
