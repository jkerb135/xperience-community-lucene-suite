<objective>
## Goal
1. **False conflict (pre-existing since 03-06 / 04-02):** after a successful save on the rule or synonym edit page, the next save of the same open form is rejected with "changed by someone else". The handler sets `model.LoadedVersion`, but the form items it returns still hold the old token. Fix: write the new version into the returned hidden form item.
2. **Conflict Reload (13-02 roadmap promise, not built):** when a rule save really conflicts, the top of the rule form shows the message with a **Reload** button. The synonym page keeps the text message; there is no handoff design for it.

## Purpose
Today, marketers who save twice get a false error and must reload, risking loss of their edits. Concurrency protection must only fire for real concurrent edits.

## Output
- The fix in both edit pages, plus a conflict flag rendered by RuleStatusFormComponent with Reload.
- Regression tests.
- An APPROVAL-CHECKS entry.
</objective>

<acceptance_criteria>

## AC-1: No false conflict
```gherkin
Given a rule (or synonym) edit page opened once
When the marketer saves, changes a field and saves again without reloading
Then both saves succeed ("Rule saved." / "Synonym saved.") and the second change is stored
And a third save also succeeds (the token keeps advancing)
```

## AC-2: Real conflicts still caught
```gherkin
Given the same rule open in two tabs
When tab A saves and tab B then saves
Then tab B is refused with the concurrency message and nothing from B is stored (rule and synonym)
And when tab B presses Save again without reloading, it is refused again: a refused (or otherwise failed) save never returns a refreshed token, so a retry cannot overwrite the other editor's change <!-- audit-added -->
```

## AC-3: Reload on a rule conflict
```gherkin
Given a refused rule save (AC-2)
Then the top of the form shows an alert "This rule was changed by someone else." with a Reload button
And Reload first asks in a Dialog "Reload the rule? Your unsaved changes are lost." (Cancel / Reload; Kentico's in-app unsaved prompt does not guard a full browser reload), and only then reloads <!-- audit-added: corrected claim -->
And the alert disappears after a later successful save
And the alert is announced (polite) and the button has an accessible name
```

## AC-4: Nothing else changes
```gherkin
Then stored JSON stays byte-identical on unedited saves, the create pages are unchanged (NavigateTo after create), and Manage-rules / Manage-synonyms gating is unchanged
```
