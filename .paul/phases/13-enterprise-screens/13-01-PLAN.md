<objective>
## Goal
Screen 3 of `project-sidecar/design/design_handoff_lucene_suite_enterprise/README.md`: the per-index Rules page handles about 500 rules.
- **Status:** derived Active / Scheduled / Expired / Disabled per rule, shown in a column and as a filter with counts.
- **Finding rules:** search by name, sort by name or priority, page sizes 25/50/100, with a range footer.
- **Bulk actions** (Manage rules only): Enable, Disable, Change priority (shift by / set to) and Delete, on selected rules or on all rules matching the filter. Each returns `{ succeeded, failed[] }` so partial failures show.
- **States:** loading, empty, filtered-to-nothing and error, as the handoff specifies.

## Purpose
Core value: "Marketers tune … without a developer." With hundreds of rules, the native listing can't show what is live, can't act on many rules at once, and hides scheduled or expired rules among active ones.

## Output
- `RuleListingPage` becomes `Page<RuleListingClientProperties>` with template `@xperience-community/lucene-suite/RuleListing`
- Pure `RuleListing` (status, filter, sort, page, counts, bulk planning) with xUnit tests
- `RuleListingTemplate.tsx` + pure `listing.ts` with node tests
</objective>

## Design (from /xbyk-admin-ui:design-screen, PLAN run 2026-10-12)
- **Classification:** listing page → surfaces on the grey desk, no wrapping Card (enterprise.md §2). Custom page template (like SearchReports) because counts, the bulk bar, select-all-matching, the range footer and Change priority exceed the native LISTING (user decision 2026-10-12). Root uses `pageStyle` (104 px gutter).
- **npm 31.9.1 exports checked:** `Table` (`selectable`, `isAllRowsSelectable`, `onSelectedItemsChange`, `preselectedRows`, `sortModel`, `renderFooter`), `NameToggleButtons`, `Pagination`, `Dialog`, `RadioGroup`/`RadioButton`, `Input`, `Select`/`MenuItem`, `Button`, `Callout`, `NotificationBarAlert`, `Spinner`, `Icon`, `Headline`, `TextWithLabel`. **Not exported:** SearchInput, SimpleStatus, ConfirmationDialog, Snackbar, skeleton components.
- **Region outline:**
  ```
  div[pageStyle] Stack XL
  ├─ header row (flex, space-between): Headline M role=heading level 1 "Rules" · Button Primary xp-plus "Create rule" (Manage only, link)
  ├─ NotificationBarAlert (load error + Retry | dismissible partial-failure warning)
  ├─ toolbar row, gap Spacing.L: Input (aria-label "Search rules", placeholder "Search by name", xp-magnifier) · NameToggleButtons "All 500 / Active 412 / Scheduled 30 / Expired 18 / Disabled 40"
  ├─ bulk bar (Manage only, ≥1 selected): sticky top Spacing.S, background-selected token, shadow-m, radius 8
  │    "{n} rules selected" (bold) · [Select all {N} matching | "All matching rules are selected."]
  │    Buttons Secondary S: Enable xp-check-circle · Disable xp-minus-circle · Change priority xp-arrows-v · Delete (destructive) xp-bin · Quinary xp-times "Clear selection"
  ├─ Table selectable (Manage only):
  │    Name (link to edit, max 40, sortable) · Priority (max 10, sortable asc default) · Status (icon + text, 13–14)
  │    · Valid from (UTC) · Valid until (UTC) (yyyy-MM-dd HH:mm) · Conditions · Actions (summaries) · row actions (Edit, Delete; quinary icon buttons, aria-labels "Edit rule "{name}"")
  ├─ range footer: "1–25 of 500 rules" · Select page size 25/50/100 (≈140 px) · Pagination
  └─ Dialogs: Delete / Disable / Change priority (RadioGroup Shift by | Set to + number Input "Lower numbers run first.")
  ```
- **Status display:** `Icon` (xp-check-circle / xp-clock / xp-times-circle / xp-minus-circle) + text in the matching status token colour (success / warning / alert / low-emphasis); the text carries the meaning, the icon is `aria-hidden`.
- **Rows:** npm Table rows cannot take focus (enterprise.md §5), so the edit page is reached through the Name link and the Edit row action, both keyboard-reachable. One-line rows; summaries ellipsize with `title`.
- **States:** loading → `Spinner` in place of the table (header and toolbar stay); empty → Callout QuickTip OnDesk "No rules yet" + "Create rule" (Manage only); filtered empty → Callout "No rules match" + "Clear filters"; error → NotificationBarAlert "The rules could not be loaded. Check the connection and try again." + "Retry", last good rows kept.
- **Results:** success → Kentico toast from the command response ("{n} rules deleted." / "enabled." / "disabled." / "Priority changed for {n} rules."); partial failure → dismissible NotificationBarAlert warning naming the first failure reason and the count.
- **Focus:** opening a dialog focuses its first control; closing returns focus to the bulk-bar button that opened it; after Delete, focus moves to the search Input.
- **Tokens:** every colour verified with `getComputedStyle` on the running admin before use (enterprise.md §1); no hex from the handoff's token list.

<acceptance_criteria>

## AC-1: Derived status is correct at the boundaries
```gherkin
Given now = 2026-10-12 10:00 UTC
Then a disabled rule is Disabled whatever its dates
And an enabled rule with Valid from 10:01 is Scheduled
And an enabled rule with Valid until 10:00 is Expired (Valid until is exclusive)
And an enabled rule with Valid from 10:00 and no Valid until is Active
And the status filter counts add up to All for the index
```

## AC-2: Search, filter, sort and paging over ~500 rules
```gherkin
Given an index with 500 rules
When a marketer searches "coffee", filters Active, sorts by Priority descending and picks 50 per page
Then only this index's matching rules show, 50 per page, with "1–50 of {n} rules"
And changing search, filter or page size resets to page 1 and clears the selection
And the List command responds in under 200 ms on the host (warm)
And returning from a rule's edit page restores search, filter, sort, page and page size (sessionStorage, per index)
```

## AC-3: Bulk actions with partial failure
```gherkin
Given a marketer with Manage rules selects 3 rules and clicks Disable, then confirms
Then the 3 rules are disabled, a toast says "3 rules disabled.", and the list reloads with the selection cleared
When one selected rule was changed by someone else after the list loaded (LastModified differs)
Then that rule is left unchanged and a warning bar reads "1 rule could not be disabled: it was changed by someone else. Reload and try again."
And Enable applies without a dialog; Delete and Disable confirm first (Delete lists up to 3 names, then "and {n} more")
```

## AC-4: Change priority
```gherkin
Given 5 selected rules with priorities 10, 20, 30, 40, 50
When "Shift by" -5 is applied
Then their priorities become 5, 15, 25, 35, 45
When "Set to" 1 is applied
Then all five have priority 1
And a non-integer, empty or overflowing value is refused in the dialog and on the server
```

## AC-5: Select all matching
```gherkin
Given a filter matching 120 rules and page size 25
When the marketer selects the page and clicks "Select all 120 matching", then Enable
Then the command receives the filter (search + status), not ids, and the server re-applies it for this index
And the toast counts the rules actually changed
```

## AC-6: Authorization and ownership
```gherkin
Given a user with Site Search → View but not Manage rules
Then the page shows no selection checkboxes, bulk bar, Create rule or Delete actions
And calling any bulk command directly is refused by the MANAGE_RULES page command permission
And ids belonging to another index are reported as failed "not in this index" and never changed
And List takes the index only from the page, never from the client
```

## AC-7: Rule changes reach search immediately
```gherkin
Given rules are disabled or deleted in bulk
When the live site searches next (any web-farm node)
Then the changed rules no longer fire, because every change goes through IInfoProvider<RuleInfo>.Set/Delete per rule (RuleProvider invalidation), never bulk SQL
```

## AC-8: States
```gherkin
Then loading shows a Spinner in place of the table with header and toolbar kept
And an index without rules shows "No rules yet" (+ Create rule for Manage users)
And a filter with no matches shows "No rules match" + "Clear filters"
And a failed List shows the error bar with Retry and keeps the last loaded rows
```

## AC-9: Filter-mode actions never touch rules the marketer did not see <!-- audit-added -->
```gherkin
Given "Select all 120 matching" is active and another user creates or edits a rule so the filter now matches 121
When the marketer confirms Delete (or Enable / Disable / Change priority)
Then the server refuses the whole command with "The matching rules changed. Reload and try again." and changes nothing
And the dialog showed the exact count that the server checks (ExpectedCount)
```

## AC-10: Bulk changes are reconstructable <!-- audit-added -->
```gherkin
Given any bulk command changes at least one rule
Then one Kentico event log entry records the action, the index, and per rule its id, name and before → after values (enabled, priority; for Delete the name, priority, enabled and dates)
And the entry is written even when some rules failed, listing the failed ids with reasons
```
