## 1. Executive Verdict

Conditionally acceptable. The fix targets the real root cause (the token is not refreshed in the returned form items), covers both pages with one helper, and keeps concurrency semantics.

Two flaws would have shipped:
- **A false claim about Reload.** The plan said Reload "goes through Kentico's unsaved-changes prompt". Kentico's prompt (observed in 13-02) is an in-app router guard. `window.location.reload()` is a full browser reload that bypasses it, so a marketer's unsaved edits would be **discarded silently**, the very outcome the plan said to avoid.
- **An unspecified failure path.** If the new helper refreshed the token on *any* response, a refused save would hand the client the new token. A second click on Save would then **overwrite the other editor's change**, turning the concurrency check into a speed bump.

## 2. What Is Solid

- **The root cause is verified on the host,** reproduced on both pages, so the fix is not a guess.
- **One shared helper for both edit pages,** searching nested categories (13-02 sections).
- **Regression tests** with a two-save round trip, plus a stale-token refusal.
- **Synonym UI unchanged** (no handoff), with the scope kept tight.

## 3. Enterprise Gaps Identified

1. Reload bypasses the unsaved-changes guard, so edits are lost silently.
2. Token refresh on failure paths would let a retry overwrite a real concurrent change.
3. A double-click Save racing two submits (Kentico disables Save during submit; unverified).
4. Synonym conflicts have no Reload button.

## 4. Upgrades Applied to Plan

### Must-Have (Release-Blocking)

| # | Finding | Plan Section Modified | Change Applied |
|---|---------|----------------------|----------------|
| 1 | Reload bypasses the unsaved guard (gap 1) | AC-3, Task 2, Task 3 | npm Dialog confirmation ("Reload the rule? Your unsaved changes are lost.") before reload; focus to the dialog and back on Cancel; host check |
| 2 | Token refreshed on failure (gap 2) | AC-2, Task 1 + tests, Task 3 | Only the success path refreshes; failures return the client's token; tests and a host check that a retry after a conflict is still refused |
