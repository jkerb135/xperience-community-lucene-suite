<objective>
## Goal
Marketers can keep a query text out of an index's suggestions without a developer:
- from a native **Blocked suggestions** page under Search tuning (list, create, delete);
- with one click on a Search reports query row.

## Purpose
Suggestions publish surfaced query text to every visitor (09-01). The blocklist is the marketer's control over what gets shown. Reports are unaffected.

## Output
- Admin pages: BlockedSuggestionListingPage and BlockedSuggestionCreatePage. There is **no edit page** (user decision): to change an entry, delete it and add it again.
- One shared validator: normalize, length, placeholder, duplicate.
- A `BlockSuggestion` page command on SearchReportsPage, plus a 4th icon row action in the query table.
- Tests, docs, and APPROVAL-CHECKS #12.
</objective>

## Design-screen output (PLAN)

**Classification:**
- Blocked suggestions = **Listing** (native C# `ListingPage`, `TemplateNames.LISTING`, on the desk, no Card).
- Create = **Edit form** (native `ModelEditPage`, `TemplateNames.EDIT`).
- Report action = a row-action addition on an existing **Dashboard** table.

```
Search tuning (section, left menu)
├─ Search reports (50) · Query tester (100) · Rules (200) · Synonyms (300)
└─ Blocked suggestions (400, Icons.EyeSlash or nearest existing; verify on the runtime)
   ├─ Header action: "Block suggestion" (Plus), only with Manage synonyms        [primary, native]
   ├─ Native search over Text (searchable)
   ├─ Columns: Text (maxWidth 60) · Match ("Exact query" / "Contains words") · Last modified (UTC, default sort desc)
   ├─ Table action: native Delete (native confirmation), only with Manage synonyms
   └─ Empty state: native listing empty pane
   Create (slug "create", native EDIT template)
   ├─ Text: TextInputComponent "Blocked text" (required; explanation states the 100-char limit and that letter case and punctuation are ignored)
   ├─ Match: RadioGroupComponent  exact;"Exact query: hide this suggestion only"
   │                              word;"Contains words: hide every suggestion containing these words"
   └─ Native Save (sticky bar). Errors after save only (native timing), as a form error message

Search reports → query table → Actions cell (non-wrapping flex, quinary borderless S icon Buttons)
   [magnifier] [plus-circle] [arrows-h] [ban-sign NEW]
   aria-label  `Block "{query}" from suggestions` · title "Block suggestion"
   disabled + visually hidden reason: browse row / placeholder row / no Manage synonyms
   Needs attention card: unchanged (its rows are no-result queries, which suggestions already exclude at ≥ 50 %)
```

**Components:**
- All native C# configuration plus the existing npm `Button`. No new React components and no custom form component.
- Feedback comes from Kentico's command-response message (toast). **No confirmation dialog:** the action is reversible from the listing, and npm 31.9.1 exports no ConfirmationDialog.
- Icons `xp-ban-sign` / `eye-slash` exist in the kit `public/icons`; confirm both in the runtime admin before use.

<acceptance_criteria>

## AC-1: Listing per index
```gherkin
Given index A has blocked entries and index B has others
When a user with Site Search → View opens A's Blocked suggestions
Then only A's entries show (Text, Match, Last modified UTC; newest first; searchable by text)
And the Create action and Delete appear only with Manage synonyms
And deleting an entry that belongs to another index by id is refused with an error message
```

## AC-2: Create with validation
```gherkin
Given a user with Manage synonyms on A's Create page
When they save text "  T-Shirt  Black! " with match "Contains words"
Then one row is stored: IndexName A, Text as entered (trimmed), MatchKey = SynonymEngine.MatchKey(text), MatchMode "word"
And they are returned to the listing with a success message
When they save text that is empty, whitespace or punctuation only (empty MatchKey), longer than 100 characters, contains {email}/{number}, or has the same MatchKey and mode as an existing entry of A
Then nothing is stored and a specific error message is shown
And the same text with the other mode, or in index B, is allowed
And Submit/Change require Manage synonyms (the page also refuses a View-only user)
And a text whose MatchKey would exceed 100 characters is refused <!-- audit-added -->
And the Create page validates that its index exists, like every routed node (opening it for a deleted index shows the native invalid-page message) <!-- audit-added -->
```

## AC-3: One-click block from the report
```gherkin
Given Search reports for A with a surfaced query "cofee"
When a user with Manage synonyms clicks the row's "Block suggestion" button
Then an exact entry for "cofee" is stored for A and a success toast names the query
And the suggest endpoint no longer returns "cofee" for A (cache dependency, no wait)
And clicking it again stores nothing and reports "already blocked"
And the button is disabled with a keyboard-readable reason for the browse row, placeholder rows and users without Manage synonyms
And the command itself requires Manage synonyms and re-validates the text (AC-2 rules) on the server: the client value is untrusted
And the success toast tells the user how to undo ("Remove it under Blocked suggestions") <!-- audit-added -->
When the index no longer exists, or the command fails (403, network)
Then an error is shown in the page's existing NotificationBar region, the last report stays visible, nothing is stored, and the button is usable again <!-- audit-added -->
And the button is disabled while its request is in flight (no double submit) <!-- audit-added -->
```
