<objective>
## Goal
On Search reports, the Needs attention card shows the five findings that affect the most searches. Each has its kind, the query, a one-line piece of evidence, links to the synonyms or rules that already apply, and one-click fixes that fit its kind. "Show all insights" opens a side panel with every finding grouped by kind.

## Purpose
This closes Phase 11 and turns reports into a to-do list a marketer can act on without a developer.

## Output
- An `Insights` page command and view model.
- Pure client mapping (kind → label, evidence, actions) with node tests.
- The NeedsAttention rewrite, the side panel and the RowActions action subset.
- Host verification, finalized docs/insights.md, and APPROVAL-CHECKS #14.
</objective>

## Design-screen output (PLAN)

**Classification:** an existing **Dashboard** (custom template, Papers per Convention 8). The Needs attention card is the md Col4 action card; the all-insights view is a **Stackable SidePanel**, like the breakdown and latency panels.

```
Needs attention (Paper md Col4, existing)
├─ SectionHeading eyebrow "Needs attention" · title "Fix these first" (h2)
├─ Summary line (low emphasis): "{n} findings · {Considered} queries checked" (+ "Showing the top 200" when Omitted/Truncated)
├─ NotificationBarInfo (only when AnnotationsFailed): "Existing fixes could not be checked."
├─ <ol aria-label="Top findings"> × ≤ 5, each <li> with a border-top divider (as now):
│   ├─ kind label (eyebrow style, low emphasis, not colour-only)
│   ├─ query text (600, overflow-wrap anywhere)
│   ├─ evidence line (smaller, low emphasis), e.g. "41 of 120 searches had no results (34 %)"
│   ├─ existing fixes (when any): "Already applies: Synonym ↗ · Rule 'Grinders' ↗" (npm Link via adminHref, opens in place)
│   └─ RowActions subset for the kind (icon buttons, one line, labelled, disabled reasons hidden-text)
├─ empty (no findings at the thresholds): fallback to the current list — "No findings at your thresholds. Top queries without results:" + up to 5 surfaced queries with no-result searches (the existing Queries NoResults call and RowActions); only when that is empty too: "Nothing needs attention in this period." <!-- audit-added -->
├─ loading: Spinner · error: NotificationBarAlert (last data kept)
└─ Button tertiary S "Show all insights" (buttonRef, opens panel) — only when findings > 5 or any were omitted

SidePanel "All insights" (Stackable, headline, returnFocus → Show all button on every close path)
├─ same summary + info bar
├─ per kind with findings: Headline S h3 "{Kind label} ({count})" + one-sentence explanation + same item list (all findings of that kind)
└─ kinds without findings omitted
```

**Kind → actions** (all reuse existing handoffs and commands; disabled with reasons as today):
| Kind | Label | Actions |
|---|---|---|
| ContentGap | No results | Add synonym · Create rule · Query tester |
| RelevanceMiss | Results not clicked | Create rule · Query tester · Block suggestion |
| BuriedAnswer | Answer buried | Create rule · Query tester |
| SlowQuery | Slow | Query tester |
| Regression | Got worse | Query tester · Create rule · Add synonym |

**Components (npm 31.9.1, confirmed):** Paper, Stack, SidePanel(Stackable), Button, Link, NotificationBarAlert, NotificationBarInfo, Divider, Spinner, Headline. No Tag/Badge for kind: text label (Tags are filter chips in native screens).

## AC-1: Insights command
```gherkin
Given a user with Site Search → View on Search reports for index A
When the client calls the Insights page command with a range
Then the server resolves the index from the page (never from the client), validates the range like Report/Queries (errors → result.error), and returns the findings with: kind, query, searches, affected, evidence fields, latency p95 label data, applied synonyms [{id, editUrl}] and fired rules [{id, name, editUrl}] (edit URLs via IPageLinkGenerator with section parameters), omitted, considered, truncated, previousIsPartial, annotationsFailed
And the command performs no writes (no analytics rows)
```

## AC-2: Needs attention card
```gherkin
Given findings exist for the range
Then the card shows the top 5 (server order: affected desc), each with its kind label in text, the query, an evidence line, existing-fix links when any, and exactly the kind's action set
And actions are pre-filled exactly as the query table's (same handoff targets; Block suggestion uses the existing command with toast)
And disabled reasons (permission, placeholder) are readable by keyboard as today
And the range change reloads findings (latest request wins; a failed load keeps the last findings with an alert)
And with no findings the card falls back to today's "queries without results" list (same data and actions as before 11-02), so small sites never lose what the card showed; only when that list is empty too is the empty sentence shown; while loading a Spinner <!-- audit-added -->
And each finding is a labelled group (`<li aria-labelledby>` on its query text) so screen readers announce the query with the kind and actions <!-- audit-added -->
```

## AC-3: All-insights panel
```gherkin
Given more than 5 findings or omitted findings
When "Show all insights" is pressed
Then a Stackable side panel lists all returned findings grouped by kind (h3 per kind with its count and a one-sentence explanation, kinds without findings omitted) with the same item layout and actions
And focus moves into the panel, and every close path (X, Escape) returns focus to the button (returnFocus)
And starting an action from the panel works the same as from the card
```

## AC-4: Native look, accessibility, no regressions
```gherkin
Given the change is complete
Then at ~670 and ~1270 px content width the card and panel have no overflow, action icons stay on one line, headings form a valid outline (h1 page, h2 card, h3 kinds), kind labels are not colour-only, and every control has an accessible name
And the query table, its row actions, Block suggestion and all other dashboard parts behave as before
And dotnet build 0 warnings, the full .NET suite, client npm tests and tsc pass
And host counts (SearchEvent, SearchDaily, Rule, Synonym, BlockedSuggestion) are unchanged after verification
```
