## Screen design (from /xbyk-admin-ui:design-screen; reference: native Content hub and kit ListingWithSecondaryMenuTemplate)

The query tester is a **listing-type** page (Convention 1): everything above the results sits on the grey background, with no Card.

```
h1 "Query tester" (Headline M, role=heading level 1)            [unchanged]
Callouts / notification bars                                     [unchanged]
Action bar (one row, flex, gap Spacing.M):
  [Input aria-label="Query", placeholder="Search — leave empty to list all documents", magnifier action, flex: 1]
  [Button "Filter" secondary, icon xp-filter-1, badge when applied]   (only when the index has facets)
Applied-filters row (only when filters are applied; Inline, spacing S):
  "Applied filters:" (low-emphasis text) · [Clear all, tertiary] · [Tag "Dimension: value" …]
Switches row (Inline, spacing L):
  [Switch Compare] [Switch Apply rules] [Switch Apply synonyms]   (rules/synonyms hidden in compare, as today)
Results (unchanged): stats row, fired rules, synonyms, hits table on the grey background
```

**Component map (npm 31.9.1, to confirm in dist/entry.d.ts):**
- `Input`: `label` is optional. `aria-label` and `placeholder` come through `NativeInputProps`.
- `Button`, `Tag`, `Inline`, `Switch`, `Stack`.
- No `SearchInput`, `FilterPanel` or `FilterStatusIndicator` in 31.9.1, so the bar is composed from the components above.
</design>

## AC-1: Native action bar
```gherkin
Given the query tester on a faceted index
Then:
  - the search box and the Filter button share one row at 669 px and at 1269 px content width;
  - the search box has no visible label or explanation text: its accessible name is "Query" and the placeholder carries the hint;
  - applied filters show on their own row below ("Applied filters:", Clear all, one Tag per value, same behaviour as today);
  - Compare / Apply rules / Apply synonyms switches sit on one row below that.
And on a non-faceted index the Filter button and chips row are absent and the search box takes the full width
And the existing behaviour is unchanged: Enter submits, latest request wins, chip click opens the panel, chip × removes the filter, Clear all clears
<!-- audit-added -->
And the accessible name "Query" is verified on the actual <input> element in the accessibility tree (read_page), not assumed from the props: if npm Input does not forward aria-label to the input, use the documented fallback (a visually hidden <label htmlFor> bound to the input id) instead
And the placeholder is fully visible (not truncated) at 669 px content width
```

## AC-2: Focus returns from every side panel
```gherkin
Given the Filter panel, the hit-detail panel or the Contact-groups panel is open
When it closes by X, Escape, Cancel, or Apply where present
Then focus returns to the control that opened it:
  - the Filter button;
  - the hit link/row, falling back to the table area as today;
  - the "Contact groups…" button.
And never stays on the document body, measured with document.activeElement after the close transition
And the return logic lives in one helper (focus.ts) shared by all three panels, with a node test proving it keeps retrying until the target holds focus (a SidePanel that steals focus late is simulated) and gives up after a bounded time without throwing
<!-- audit-added -->
And the helper never fights the user: it refocuses only while focus is on the document body, null, or inside the closing panel. Once the user (or anything else) puts focus on another element outside the panel, it stops immediately (node-tested: a user Tab to another button during the retry window is not overridden)
And when the Filter panel was opened from a chip, focus returns to that chip if it still exists after Apply/Cancel, else to the Filter button (Convention 8: the opener)
```

## AC-3: No collapsed gaps
```gherkin
Given any Suite client template
Then no Row is a direct child of a Stack (or of a fragment inside a Stack); each is wrapped in a plain <div>
And the reports page's Period card → KPI tiles gap and the compare note → first column gap both measure 24 px (Spacing.XL) at both widths
```

    **focus.ts:** export a pure `returnFocus(target: () => HTMLElement | null | undefined, schedule = requestAnimationFrame, now = performance.now, doc = document)`. Behaviour:
    - Each frame, while `doc.activeElement !== target()` and less than 1000 ms have passed, call `target()?.focus()`.
    - <!-- audit-added --> Only while `doc.activeElement` is null, `doc.body`, or inside the closing panel (pass a `panel: () => Element | null` predicate). Any other focused element means the user moved on; stop.
