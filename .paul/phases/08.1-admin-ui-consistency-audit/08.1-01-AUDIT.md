# Enterprise Plan Audit Report

## 1. Executive Verdict

Conditionally acceptable as written. The plan is read-only with a blocking decision before any fix, which is the right shape. But its two core outputs could not be defended as written:
- **Severity** was left to taste.
- **The reference** was ambiguous (native screen vs kit repo vs npm). This project has already been burned by the kit repo being ahead of the 31.9.1 runtime (08-01).

On top of that, the evidence lived only in git-ignored screenshots, so a finding could not be re-checked later. With the upgrades below applied, I would approve it.

## 2. What Is Solid

- **Read-only boundary, with fixes split into later plans behind a decision checkpoint.** Findings can't leak into half-applied markup, and fix scope is a user decision, not an audit side effect.
- **Native Kentico screens as ground truth.** This targets the actual complaint ("not like the rest of the admin") rather than kit-isolated validation, which already passed and missed the drift.
- **Exported-component check per fix** (dist/entry.d.ts). This prevents proposing fixes the 31.9.1 package cannot deliver (03-02 FilterPanel lesson).
- **"Not observed" instead of assumed states.** This keeps the findings honest about the View-only gap.
- **Fix plans grouped by convention, not by screen.** This avoids five plans each re-solving the card and toolbar question.

## 3. Enterprise Gaps Identified

1. **Reference precedence undefined.** The kit previews, npm typings and native screens can disagree. Without an order, the auditor picks whichever supports the finding.
2. **Severity criteria subjective.** Must/Should/Could had labels but no tests. A different auditor would rank differently, and the fix scope decision rests on these ranks.
3. **Evidence not reproducible.** Screenshots are git-ignored and the capture setup was unrecorded: content width depends on admin nav state, zoom and viewport, and the npm version can change. A finding that can't be re-observed can't be verified as fixed.
4. **Host side effects unproven.** The plan *asserts* read-only, but query tester and item-picker searches run on the host. They are expected to be untracked, but nothing measured it. A capture session that wrote analytics rows would pollute the report data the Phase 8 approvals rely on.
5. **Accessibility rubric undefined.** "Accessibility" was a rubric area with no procedure, so it would get skipped or be inconsistent across screens.
6. **Silent drop of Must findings.** The decision options allow "custom" picks with no rule that every Must is either planned or explicitly declined.

## 4. Upgrades Applied to Plan

### Must-Have (Release-Blocking)

| # | Finding | Plan Section Modified | Change Applied |
|---|---------|----------------------|----------------|
| 1 | Reference precedence undefined | AC-2 | Native 31.9.1 runtime > npm 31.9.1 exports/typings > kit repo previews. A kit-only look is never a finding by itself |
| 2 | Severity subjective | AC-2 | Fixed criteria. Must = clipping/overflow, a11y failure, hard-coded or undefined token, or container differing from the native screen of the same type. Should = the same pattern differing across Suite screens. Could = the rest |

### Strongly Recommended

| # | Finding | Plan Section Modified | Change Applied |
|---|---------|----------------------|----------------|
| 1 | Evidence not reproducible | AC-1, AC-2, verification | Capture setup recorded: commit, npm version, viewport + JS-measured content width, nav state, zoom, index/range/query. Each finding quotes its computed values/DOM so it stands without screenshots |
| 2 | Host side effects unproven | AC-1, Task 1 step 6, verification | Before/after counts of LuceneSuite_SearchEvent, _Rule, _Synonym; stop on any difference |
| 3 | Accessibility procedure missing | Task 1 step 7 | Tab pass (focus ring, accessible names via the accessibility tree), side-panel focus return, heading outline per screen |
| 4 | Must findings could be dropped silently | AC-4, verification | Every Must is mapped to a fix plan or a user-reasoned "won't fix" |

### Deferred (Can Safely Defer)

| # | Finding | Rationale for Deferral |
|---|---------|----------------------|
| 1 | 200 % zoom / reflow (WCAG 1.4.10) and high-contrast mode | Two widths cover the reported problem; record as a candidate convention for the fix plans if the audit shows width-related breakage |
| 2 | View-only permission states | No View-only user on the host; creating a role changes host data. Marked "not observed"; revisit at the milestone review (already an APPROVAL-CHECKS #6 note) |
| 3 | Live-site widget styling | Out of the user's complaint and of this phase; site CSS owns it |

## 5. Audit & Compliance Readiness

- **Evidence:** after the upgrades, each finding carries quoted computed values and a recorded setup, so it is re-checkable after a fix. The screenshots stay convenience-only.
- **Silent failures:** a host write during capture is now detected (row counts). A dropped Must is now impossible without a recorded reason.
- **Reconstruction:** the commit hash + npm version + widths pin what was audited. Fix plans can cite finding ids.
- **Ownership:** the scope decision is explicitly the user's (checkpoint). The auditor owns the evidence.

## 6. Final Release Bar

- **Must be true before this ships:**
  - every AC-1 surface is captured or marked "not observed";
  - findings follow the fixed severity criteria and precedence;
  - host counts are unchanged;
  - the user decision is recorded with every Must mapped.
- **Remaining risk:** the native reference screens themselves vary slightly between Kentico apps. The conventions pick one per pattern and cite it, which is acceptable.
- **Sign-off:** I would sign off on the plan as amended.
