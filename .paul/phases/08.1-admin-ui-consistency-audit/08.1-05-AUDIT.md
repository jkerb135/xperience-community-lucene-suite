## 1. Executive Verdict

Conditionally acceptable. The plan fixes S4 at its root cause: one gating rule instead of per-screen patches. It touches only client presentation, and server validation and Save stay authoritative.

Its accessibility choice would have backfired, though. `role="alert"` on errors that a 400 ms server re-validation keeps refreshing would interrupt screen-reader users on every keystroke after the first blur. That trades a visual annoyance for an auditory one. With polite live regions bound to their groups, and an explicit blur rule, I would approve it.

## 2. What Is Solid

- **One node-tested `isShown` rule for every editor.** This prevents the per-component drift that caused S4.
- **Server validation, JSON shapes and native Save are untouched.** A presentation change cannot lose data or let invalid rules save.
- **Load-failure alerts stay.** The plan separates "something failed" (alert bar) from "your input is wrong" (field error), which is the native split.
- **Existing remove-focus behaviour is kept explicitly** in AC-1.

## 3. Enterprise Gaps Identified

1. **Assertive re-announcement.** `role="alert"` re-announces whenever the text changes, and server re-validation while typing changes it often.
2. **Undefined "leaving the group".** Clicking empty page space gives `relatedTarget = null`. Without a rule, the group might never count as touched until Save.
3. **Read-only mode unaddressed.** View-only users must not see new icon buttons or errors. The host has no View-only user, so this can only be held by code and stated.
4. **Ref continuity.** Converting the remove buttons to icon-only must keep the `buttonRef`s the focus-after-remove logic relies on.
5. **Per-page column hiding (C1).** The column set can change between result pages.
