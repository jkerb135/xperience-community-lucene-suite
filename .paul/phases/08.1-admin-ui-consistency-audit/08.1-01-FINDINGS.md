## Your reported issue: query tester search bar and filter chips

**Diagnosis.** The chip is fine. The npm `Tag` renders exactly like native Content hub's chip:
- background `rgb(6,119,168)`, 32 px high, 8 px radius, 14 px text.

The search box is also the native pill: 40 px, 1 px `rgb(140,140,140)`.

Native pages don't put these in a white card either. Content hub and the kit's `ListingWithSecondaryMenuTemplate` keep the action bar and the applied-filters row on the grey background.

**What looks wrong is the layout around them** (`QueryTesterTemplate.tsx:239-303`):
- **The search is built as a form field, not a toolbar.** It is `Input` with a visible "Query" label and explanation text under it. Native uses an unlabelled search box with a placeholder in one action bar: `[search, flexible width][FILTER]`.
- **Filter is detached.** The Filter button sits on its own line below the search, under three switches (Compare / Apply rules / Apply synonyms). At 669 px those switches stack under the search; at 1269 px they move to a right-hand column. Native puts Filter on the same row as the search.
- **Chips share a row with the Filter button.** Native puts "Applied filters: ⊗ Clear all [chips]" on its own row under the action bar.

Together this reads as a loose form floating on the background, which is what you saw. Evidence: `qt-default-1100.jpg`, `qt-chips-1100.jpg`, `qt-toolbar-zoom-1100.png` compared with `ref-contenthub-chips-1100.jpg`.

## Conventions (all Suite admin screens)

1. **Page types.**
   - *Listing-type* (query tester results, future blocklist-like custom listings): match native listings. Heading, then the action bar, then the applied-filters row, all on the grey background. Table rows are white on the grey background, with no wrapping `Card`. (Ref: Content hub, `ListingWithSecondaryMenuTemplate`.)
   - *Dashboard-type* (reports): one `Card` per section, `Card headline` used as the h2, KPI tiles as `InfoCard`.
   - *Forms*: native edit pages only. Custom form components never add a 24 px heading; repeated blocks use `Headline S`, inside a bordered `Paper` or the existing inner card.
2. **Spacing.**
   - `Stack spacing XL` (24 px) between page regions.
   - `M` (12 px) inside a card.
   - `S` (8 px) between a label and its control group.
   - Never put a `Row` directly in a `Stack`; wrap it in a `<div>`.
3. **Action bar.** One row: the search `Input` (`aria-label`, placeholder, no visible label, flexible width) plus the `Filter` button (secondary). Page-level switches go on their own `Inline` row below. The page's primary action, if any, goes first (native order).
4. **Applied filters.** Their own row under the action bar: "Applied filters:" in low-emphasis text, a tertiary `Clear all` button, then one `Tag` per value ("Dimension: value"). Clicking a chip opens the panel; × removes the filter.
5. **Tables.** npm `Table`, one-line rows (48 px). Row actions in a single "Actions" `DropDownActionMenu`, or at most one inline labelled button; never stacked. Headers must not be truncated at 669 px; hide low-priority columns below md instead.
6. **Headings.** Page title: `Headline M` inside `role=heading aria-level=1` (native size). Sections: h2. Sub-blocks: h3 with `Headline S`. No skipped levels.
7. **States.**
   - Loading: `Spinner` in place.
   - Load or save failures: `NotificationBarAlert` at the top of the affected card or panel.
   - Field validation: the field's own error text, only after Save or blur, never on add.
8. **Side panels.** Focus moves into the panel on open, and returns to the opener on every close path (X, Esc, Cancel, Apply). This is covered by a test.
9. **Widths checked.** 669 px and 1269 px content width (1100 and 1700 viewports), navigation expanded.

10. **Dashboard pages (added 08.1-03).**
    - **Layout:**
      - Period toolbar on the desk: preset toggle, ‹ › stepping by the range's own length, then "range (UTC), compared with previous".
      - A KPI strip Paper with Volume and Quality groups of compact selectable tiles (`button aria-pressed`, one accent).
      - Trend Paper (Col8) with "Show breakdown" (side panel), next to Needs attention + Performance (Col4).
      - The full-width query table last.
    - **Style:**
      - Eyebrow labels: uppercase, 0.12em, smaller, low-emphasis.
      - Deltas coloured by meaning, with hidden "better"/"worse" text.
      - Runtime tokens only; AA contrast checked.
      - Secondary detail (insights, latency histogram) goes in side panels that return focus.
    - **Gotcha:** npm 31.9.1 `Spacing` values are strings (`"1px"`). Never append a unit.
