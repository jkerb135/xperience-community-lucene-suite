## Screen design (from /xbyk-admin-ui:design-screen; dashboard-type page, Convention 1)

The reference composition is the Community Portal reporting screen, rebuilt from npm parts.

```
h1 "Search reports"                                            (page title, native size)
Period toolbar (on desk, action-bar style, Convention 3):
  NameToggleButtons 7d | 30d | 90d | 12m | Custom  ·  "Sep 12 – Oct 11, 2026 vs Aug 13 – Sep 11" (low-emphasis)  ·  Spinner
  (Custom → DateTimeRangeInput row below, as today)
Notices (callouts on desk, as today)
Row (Col12 / md Col8 + Col4):
  ┌ Paper (white, RadiusL) — FOCUS ─────────────────┐  ┌ Paper — INSIGHTS ─────────────┐
  │ eyebrow "FOCUS VIEW"                            │  │ eyebrow "INSIGHT NOTES"        │
  │ h2 {metric name}  · description (definition)    │  │ h2 "{metric} snapshot"         │
  │ Tile grid (3 per row md+, 2 below):             │  │ Insight rows (bordered tiles): │
  │   6 selectable tiles = <button aria-pressed>    │  │  RANGE TOTAL / AVERAGE         │
  │   eyebrow caption · big value · definition      │  │  PREVIOUS PERIOD + delta       │
  │   delta (coloured: better/worse) · "vs prev."   │  │  DAILY AVERAGE                 │
  │   selected = accent surface (runtime tokens)    │  │  PEAK DAY · LOWEST DAY         │
  │ Focus chart: bars per day + 7-day rolling line, │  │ Pattern readout (tinted panel):│
  │   legend, not-final pattern, "Show as table"    │  │  active days x/N · latest vs   │
  └─────────────────────────────────────────────────┘  │  7-day avg · share of no-result│
                                                       └────────────────────────────────┘
Card "PERFORMANCE · Latency" (existing content)
Card "QUERIES · Queries" (sort toggle, one-line table, Actions menu per row, paging, (other) line)
```

**Component map (npm 31.9.1, confirm in dist/entry.d.ts during APPLY):**
- `Paper` (`elevation`, `borderRadius` `BorderRadius.RadiusL`) for the two panels; `Card` for Latency and Queries.
- `Row` / `Column` (wrapped per Convention 2), `Stack`, `Inline`, `NameToggleButtons`, `DateTimeRangeInput`, `Spinner`, `Callout`.
- `DropDownActionMenu` + `MenuItem` (`primaryLabel`, `disabled`, `tooltipText`) for row actions; `Button` (labelled trigger).
- `Headline` inside role=heading.
- The tiles are native `<button aria-pressed>` with inline token styles: the npm `InfoCard` takes strings only and is not selectable.

**Flare rules (become Convention 10):**
- Eyebrow labels: uppercase, letter-spacing 0.12em, `smaller`, low-emphasis token.
- One accent tile only (the selected metric).
- Deltas coloured by meaning, not by sign: for no-result rate and avg. position, down is good.
- White panels on the grey background with a 16 px radius; nested insight tiles bordered with a 1 px `--color-border-*` runtime token.
- All colours resolved from runtime tokens and verified with getComputedStyle (08-01 rule).
</design>

## AC-1: Daily series for every KPI
```gherkin
Given SearchReportService.Trend for an index and range
Then each ReportDay additionally carries ConvertedSearches, Clicks, ClickPositionSum and SessionDays (additive; existing fields and the query count unchanged)
And SearchReportsDay exposes them
And a DB test proves that, summed over the days, each field equals the Overview totals for the same range
```

## AC-2: Focus panel with selectable tiles
```gherkin
Given a loaded report
Then six tiles show Searches, No-result rate, CTR, Conversion rate, Avg. click position and Session-days, each with:
  - an eyebrow caption;
  - a large value;
  - a one-line definition;
  - the previous-period delta, coloured good/bad by metric direction (neutral text when there is no comparison).
And exactly one tile is selected (default Searches). It is a <button aria-pressed="true"> with the accent surface; the others are aria-pressed="false". Selecting another updates:
  - the panel title and description;
  - the chart: daily values, plus a 7-day rolling average line ignoring days without data, not-final days patterned as today, and the table view;
  - the insight notes.
  This happens without a new server request.
And the selected metric is kept per index with the range/sort/page state (sessionStorage, 08-02 helper) and restored when valid
And rate metrics chart the daily rate (null when the denominator is 0, shown as a gap, not 0)
<!-- audit-added -->
And the tiles sit in a role="group" labelled "Metric"; the focus panel title is the chart's accessible label source, so a screen reader hears the new metric after selection (the chart's role="img" summary and table caption name the selected metric and range)
And good/bad meaning is never colour-only: each delta keeps its signed text and adds a visually hidden "better" / "worse" (and the tone is also exposed in the table view of the insights)
And the accent tile's text and the delta colours meet WCAG AA contrast (≥ 4.5:1) against their surfaces, computed from the resolved runtime colours
```

## AC-3: Insight notes
```gherkin
Given the selected metric
Then the insights panel shows:
  - range total (counts) or range value (rates);
  - previous period value and delta;
  - daily average;
  - peak day and lowest day (by value, complete days only, date shown);
  - a pattern readout:
    - active days (days with ≥ 1 search) / days in range;
    - latest complete day vs its 7-day average;
    - share of searches with no results.
And every figure comes from pure, node-tested helpers in report.ts (series, rolling average, insights), including empty, all-null and single-day ranges
<!-- audit-added -->
And when no day in the range is complete, peak/lowest/latest show the em dash with "No complete day yet" (never a not-final day)
And when the previous period is partial (PreviousIsPartial), the previous value and delta show "No comparison" exactly as the tiles do
```
