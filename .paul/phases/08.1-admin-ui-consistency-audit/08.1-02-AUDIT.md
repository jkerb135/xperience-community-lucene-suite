## 1. Executive Verdict

The plan was conditionally acceptable as written. Its scope is tight, it changes no behaviour, and the focus fix is centralised and unit-tested.

One must-fix: the focus helper as specified (retry for 1 s until the target holds focus) would steal focus back from a keyboard user who moves on during that second. That would turn an accessibility fix into a new accessibility regression.

The plan also assumed, without checking, that `aria-label` reaches the `<input>` element. With both corrected I would approve it.

## 2. What Is Solid

- **One shared helper with an injectable scheduler, clock and document.** The timing bug is testable in node, the same pattern as the 03-02 state helpers.
- **The scope boundary to 08.1-03** (tables, headings, validation) keeps this plan to one convention group.
- **Behaviour-preservation list in AC-1.** Enter, latest-request-wins, chip interactions and Clear all are named, so the restructure can be checked against them.
- **The non-faceted index is included.** It is the other branch of the toolbar.
- **Host counts before and after,** carried over from the 08.1-01 audit.

## 3. Enterprise Gaps Identified

1. **Focus stealing.** An unconditional retry loop fights the user. If someone presses Tab or clicks elsewhere within 1 s of closing, focus is yanked back.
2. **Unverified accessible name.** `aria-label` goes through `NativeInputProps`, but the npm `Input` may spread native props onto a wrapper rather than the `<input>`. Removing the visible label without checking could leave the field unnamed (a Must under 08.1-01's criteria).
3. **Wrong focus target when a chip opened the panel.** The plan hard-codes the Filter button, but Convention 8 says "the opener", and chips open the panel too.
4. **Sweep sites unchecked visually.** Wrapping a `Row` changes which element carries the negative gutter margin. Only two of the sites were going to be checked on screen.
5. **The placeholder now carries the hint, unchecked at narrow width.** A truncated hint loses the information the removed explanation text used to give.

## 4. Upgrades Applied to Plan

### Must-Have (Release-Blocking)

| # | Finding | Plan Section Modified | Change Applied |
|---|---------|----------------------|----------------|
| 1 | The focus helper can steal focus from the user | AC-2, Task 1 action + tests, Task 3 | Refocus only while focus is null, on body, or inside the closing panel; stop as soon as focus is elsewhere. Node test plus a host Tab-away check |

### Strongly Recommended

| # | Finding | Plan Section Modified | Change Applied |
|---|---------|----------------------|----------------|
| 1 | Accessible name assumed | AC-1, Task 3 | Verify "Query" on the `<input>` with read_page; fallback is a visually hidden `<label htmlFor>` |
| 2 | Chip-opened panel returns to the wrong control | AC-2, Task 1 tests, Task 3 | Return to the chip if it still exists, else the Filter button |
| 3 | Sweep sites not checked visually | Task 3 | Every changed Row site checked at both widths (gap, no overflow) |
| 4 | Placeholder truncation | AC-1, Task 3 | Placeholder fully visible at 669 px |

### Deferred (Can Safely Defer)

| # | Finding | Rationale for Deferral |
|---|---------|----------------------|
| 1 | Automated browser (e2e) test of focus return | The project has no e2e harness. The node test covers the logic; the host check covers the integration |
| 2 | Future npm SidePanel versions changing focus timing | The 1 s budget is recorded in KNOWN-LIMITATIONS; re-check on npm upgrade |
