<design>
## Design (from /xbyk-admin-ui:design-screen + enterprise.md)

The editors live inside **native** edit forms (Convention 1, form pages). The custom components must look like native field groups:

```
Conditions (native field label)
┌ bordered Paper (RadiusM, 1px --color-paper-border) ─────────────────────────┐
│ "Condition 1"  (Headline S, role=heading level 3)          [🗑 icon button] │  ← C2: remove in header
│ [Query ▾] [Text ____________________]                                       │
│   error text under the field (after blur / failed save)                     │
│ [Facet ____] [Value ____]                                      [🗑]         │  ← M6: icon-only remove, never overflows
│ [+ Add facet] [+ Add context]                                               │
└─────────────────────────────────────────────────────────────────────────────┘
[+ Add condition]
```

- **Row remove:** icon-only `Button` (`xp-bin`, quinary, borderless, size S) with `aria-label="Remove facet 2 of condition 1"` and a title; the column holds one 32 px icon.
- **Errors:** a field error uses the field's own `invalid` + `validationMessage`. Group-level errors (facets/contexts set, terms count, unmatched) render as inline text with `role="alert"` and `--color-alert-text` under the group, never as `NotificationBarAlert`. All of them wait for blur of the group or a failed save (`props.invalid`).
</design>

## AC-1: No overflow (M6)
```gherkin
Given Create rule with a condition holding 2 facets and 2 contexts, 2 boosts, pins and hides
Then at 669 and 1269 px content width no control extends past the form card (measured)
And every row remove is an icon-only button whose accessible name says which row it removes
And after a remove, focus moves to the next row's remove button, or to the group's Add button when none is left (existing focus behaviour kept)
```

## AC-2: Heading scale (S3) and remove placement (C2)
```gherkin
Given a condition block
Then its title "Condition N" is Headline S (16 px) with role=heading aria-level=3 (the native field label above is the parent context)
And "Remove condition" is an icon-only button in the block's header row, right-aligned, labelled "Remove condition N"
```

## AC-3: Error timing and pattern (S4)
```gherkin
Given a new rule or synonym
When a condition, facet, context, boost, pin or term is added and nothing else happens
Then no error is shown anywhere
When the user leaves the group (blur out of it) or Save fails
Then errors appear:
  - under their field;
  - group errors as inline role="alert" text in --color-alert-text under the group.
And no NotificationBarAlert is rendered inside any rule or synonym form component
  (load/command failures, e.g. the item picker search, keep their alert bars)
And the gating rule is one shared, node-tested helper used by every editor:
  shown when props.invalid, or when the path or its group was touched
<!-- audit-added -->
And inline errors are announced politely, not assertively: aria-live="polite" with a stable id that the group references via aria-describedby. role="alert" is not used, because the 400 ms server re-validation while typing would re-announce on every change
And focus leaving a group counts as leaving when relatedTarget is null or outside the group (clicking empty page space or Save both count)
And read-only forms (View permission, FormEditMode.ReadOnly) show no remove/add buttons and no errors, as today
```

## AC-4: Polish
```gherkin
Then:
  - the query tester hides a key-field column when no hit on the page has a value for it (C1: Body);
  - the synonym "Add a term" field sits Spacing.M below the term list (C3).
```
