<objective>
## Goal
Marketers manage an index's synonyms in the admin, and see what synonyms did in the query tester:
- **Synonyms listing** per index (native listing): terms summary, kind, enabled, last modified; create, edit and delete with Manage synonyms; View is read-only.
- **Synonym editor** (native edit page): Kind (two-way / one-way), Input (one-way only), Enabled, and a **tag/chip terms editor** (user decision 2026-10-11) with per-term errors.
- **Query tester**: an "Apply synonyms" switch beside "Apply rules" (user decision), a "Synonyms applied (N)" region linking each applied synonym to its edit page (user decision), and a warning when synonyms failed.

## Purpose
Core value: "Marketers tune … search without a developer." After this plan synonyms can be created and checked in the admin without SQL. It closes Phase 4.

## Output
- `SuiteSearchRequest.ApplySynonyms` (default true).
- Admin pages, edit model, server-only validation rules, terms form component with a Validate command, listing summaries.
- Client terms chip editor and query tester additions, with node tests.
- .NET tests and a checkpoint.
</objective>

## Design (from /xbyk-admin-ui:design-screen, PLAN run 2026-10-11)
- Listing and editor: native Kentico `ListingPage` / `ModelEditPage` (EditTemplate), like rules (03-06). Native `RadioGroupComponent`, `TextInputComponent` + `VisibleIfEqualTo`, `CheckBoxComponent` exist in 31.9.1 [Certain: Kentico.Xperience.Admin.Base.Shared.dll].
- Terms chips: npm `Tag` with `onRemoveClick` renders a focusable `<button aria-label="remove {label}">` and hides it when `readOnly` [Certain: kit Tag.tsx]. Tag has no invalid state → per-term errors are a separate line under the chips.
- Region outline:
```
Synonyms listing (native ListingPage, Search tuning section, order 300)
├─ header action: "Create synonym" (Manage synonyms only)
├─ columns: Terms ("grinder ⇔ mill" / "tee → t-shirt, tees"), Kind, Enabled, Last modified (searchable on Terms + Input)
└─ row actions: Edit (all), Delete (Manage synonyms, native confirmation)

Synonym editor (native EditTemplate)
├─ RadioGroup "Kind": Two-way (every term finds the others) / One-way (the input finds the terms)
├─ TextInput "Input term" — VisibleIfEqualTo(Kind, oneWay)
├─ Custom "Terms" (SynonymTermsFormComponent)
│   FormItemWrapper (label, explanation, invalid, validationMessage) → Stack(M)
│   ├─ Inline(S): Tag per term (onRemoveClick; readOnly in View mode)
│   ├─ per-term errors: one line each, "“t-shirt.”: Duplicate term." (token alert colour, role=alert on change)
│   ├─ Row: Input "Add a term" (Enter adds) | Button secondary "Add" (disabled at 20 or empty)
│   └─ NotificationBarAlert for errors without a term path
├─ CheckBox "Enabled"
└─ hidden LoadedVersion (concurrency)
Query tester additions
├─ toolbar: Switch "Apply synonyms" stacked under Switch "Apply rules"
├─ NotificationBarWarning "Synonyms could not be applied — the original text was searched." when SynonymsFailed
└─ "Synonyms applied (N)" region (role=heading level 2) after Fired rules: LinkButton "grinder → mill" per substitution (plain text "… (deleted)" when the synonym no longer exists); "No synonyms applied"
```

## AC-1: Synonyms listing per index
```gherkin
Given the Search tuning section of an index
Then a "Synonyms" page lists only that index's synonyms with Terms summary, Kind, Enabled and Last modified, searchable by term
  - two-way summary: terms joined by " ⇔ "; one-way: "input → t1, t2"; an invalid row shows "Invalid — open to fix"
And "Create synonym" and Delete appear only with Manage synonyms; Delete is gated on Manage synonyms server-side and refuses a synonym of another index
And a View-only user sees the listing and can open a synonym read-only
```

## AC-2: Synonym editor
```gherkin
Given the create or edit page
Then Kind is a radio group (Two-way default / One-way), Input appears only for One-way, Terms is the chip editor, Enabled defaults on
And saving validates with SynonymSerializer:
  - term errors (terms[i]) show on the matching chip line; input errors on Input; kind errors on Kind
  - terms are stored normalized as a JSON array; Input stored empty for two-way
And create navigates to the new synonym's edit page; edit stays and reports "Synonym saved."
And ownership (synonym belongs to the page's index), optimistic concurrency (LastModified) and Manage synonyms gates on Submit/Change apply exactly as for rules (03-06)
And View-only users get a read-only form with no Save
```

## AC-3: Terms chip editor
```gherkin
Given the Terms component (editable)
Then each term is a Tag with a focusable remove button; Enter or "Add" adds the typed term and clears the input, keeping focus there
And the client refuses, with a message on the input: an empty term, a term already present (compared by MatchKey rules: case, whitespace, edge punctuation), more than 100 characters, and adding past 20 (Add disabled)
And removing a chip moves focus to the next chip's remove button, else the previous, else the input
And server errors from the component's Validate command (debounced, stale answers dropped, shown after a change or a failed save) appear per term; errors without a term path appear in a NotificationBarAlert
And in read-only mode chips have no remove buttons and there is no input
<!-- audit-added -->
And a typed but not yet added term is never lost silently: leaving the Add input (e.g. clicking Save) adds it when valid; when invalid it stays in the input with its error
And the chips are a labelled list (role="list", aria-label "Terms", one listitem per chip); the Add input is labelled and limited to 100 characters
```

## AC-4: Query tester shows and toggles synonyms
```gherkin
Given the query tester
Then an "Apply synonyms" switch (default on) sends ApplySynonyms with every search and re-runs the current search when switched; it stays enabled while a search runs
And SuiteSearchRequest.ApplySynonyms = false skips expansion entirely (no AppliedSynonyms, SynonymsFailed false)
And "Synonyms applied (N)" lists each substitution "term → replacement" in order, linked to the synonym's edit page (one WhereIn query for existence in this index); a deleted synonym shows without a link
And SynonymsFailed shows the warning bar; with synonyms off, no region and no warning
```

## AC-5: Design validation and live check
```gherkin
Given the listing, editor and query tester in the browser pane
Then the region outlines hold, only npm-exported components are used (props checked), tokens only, no unstyled text
And keyboard use works: add/remove chips, radio Kind, switches, applied-synonym links
And layout holds at ~790 and 1440 px
And a two-way "grinder ⇔ mill" and a one-way "tee → t-shirt" created in the UI change query tester results immediately (cache cleared by the save), then are deleted in the UI
```
