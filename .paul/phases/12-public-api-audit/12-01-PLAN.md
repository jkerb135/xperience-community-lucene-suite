<objective>
## Goal
The three packages' public surface becomes intentional, small and frozen:
- every public type is classified;
- unneeded ones are made internal;
- two known rough edges are fixed before the first release;
- Microsoft PublicApiAnalyzers fails the build on any undeclared API change.

## Purpose
This is the layered-packages promise (PROJECT key decision, 2026-10-12): Core + Admin alone suffice for a custom UI, and Widgets is extensible. A baseline makes every later change a visible, reviewed diff.

## Output
- 12-01-INVENTORY.md.
- Code cleanups and internalizations.
- PublicAPI.Shipped/Unshipped.txt per package.
- docs/public-api.md (the supported boundary).
- APPROVAL-CHECKS #15.

## Already true (no work)
- XML docs on every public member: GenerateDocumentationFile + TreatWarningsAsErrors already fail on CS1591.
- The "build your own UI / author your own widget" guide: docs/samples.md (a)–(e) and docs/widgets.md (overriding markup, endpoints) cover it. This plan only links them from public-api.md.

## Decided (user, 2026-10-12)
- Baseline = Microsoft.CodeAnalysis.PublicApiAnalyzers.
- Admin-side services (reports, insights, rule/synonym/blocklist management) stay internal; Phase 12 documents the boundary.
- Breaking cleanups now (nothing released): `LogClick(SearchClick)` and one namespace for MapLuceneSuite*.
</objective>

## AC-1: Inventory and classification
```gherkin
Given the three packages
Then 12-01-INVENTORY.md lists every public type (namespace, kind, package) with one class each:
  Supported API (documented, for site developers),
  Framework-required (public only because Kentico/ASP.NET needs it: admin UIPages, page-command DTOs, client-property classes, form components, widget properties, view components),
  Internalize (no external use)
And every Internalize type is made internal (tests keep access through the existing InternalsVisibleTo), with the build and tests still green
And no type is made public that wasn't (the surface only shrinks or stays)
And types a host needs to customize the Widgets package stay public and Supported: view models used by the overridable Razor views (docs/widgets.md "Overriding the markup"), widget property classes, options classes bound from appsettings <!-- audit-added -->
And after internalizing, a runtime smoke check on the host passes: every Suite admin page opens (index listing, reports incl. insights, query tester, rules, synonyms, blocked suggestions), /site-search renders results and facets, POST /lucenesuite/events → 202, GET /lucenesuite/suggest → 200; no new errors in the host log <!-- audit-added -->
```

## AC-2: SearchClick
```gherkin
Given ISearchInteractionLogger
Then LogClick takes one `SearchClick` record (SearchId, Sequence, ItemGuid, Position, EventId?, QueryText?, ResultTitle?) whose constructor or Validate keeps today's argument rules and exception types (empty GUIDs → ArgumentException; sequence < 1 or position outside 1–1000 → ArgumentOutOfRangeException)
And LogConversion is unchanged
And every caller (Widgets endpoint, tests, test fakes, docs samples) is updated; behaviour, analytics rows and activities are unchanged (existing tests pass with only call-site edits)
```

## AC-3: One Widgets namespace
```gherkin
Given a host that uses the Widgets package
Then AddLuceneSuiteWidgets, MapLuceneSuiteEvents and MapLuceneSuiteSuggestions are all in namespace XperienceCommunity.Lucene.Suite.Widgets
And the CommunityProjects host compiles with a single `using XperienceCommunity.Lucene.Suite.Widgets;` for them (its two sub-namespace usings removed, bytes otherwise preserved)
And endpoint routes and behaviour are unchanged
```

## AC-4: Baseline enforced
```gherkin
Given Microsoft.CodeAnalysis.PublicApiAnalyzers in all three packages (PrivateAssets=all, version pinned in Directory.Packages.props)
Then each package has PublicAPI.Shipped.txt (empty: nothing released) and PublicAPI.Unshipped.txt (the whole current surface)
And adding, removing or changing any public member without editing those files fails the build (RS0016/RS0017 as errors), proven once by a throwaway change that is reverted
And the test project and the host are not affected (analyzer only on the three packages)
```

## AC-5: Documented boundary
```gherkin
Given docs/public-api.md (front matter, nav_order 85)
Then it states the supported API per package (from the inventory), what is public only for Kentico (not supported for direct use), what is deliberately internal (reports, insights, rule/synonym/blocklist management — admin only), how the baseline works for contributors, and links samples.md / widgets.md as the custom-UI guide
And the pages whose code changed (contract §3 LogClick, widgets.md/samples.md/getting-started.md usings) show the new code
```
