<objective>
## Goal
Show marketers what visitors actually click, and let them act on it.
- **Card:** a "Top clicked items" card on Search reports for the selected range, showing the top 10 items by clicked searches. Columns are sortable by clicked searches, conversions and average click position.
- **Side panel:** "All clicked items" lists every item for the range, paged.
- **Row actions:** "Pin in a new rule" and "Hide in a new rule" open rule create with the item pre-filled.

## Purpose
- Phase 14 promised a report on the new item data.
- Seeing popular items next to the queries that lead to them is the main input for pins, hides and (in Phase 19) the popularity boost.

## Output
- Report-service query and page command.
- React card and panel.
- Handoff extension and rule-form consumers.
- Tests, docs, approval entry.
</objective>

## AC-1: Top items data
```gherkin
Given the reports page for an index and a valid range (same validation as Report)
When the TopItems command runs with a sort (clickedSearches | conversions | avgPosition) and paging (page, pageSize 10/25/50)
Then it returns, per item with ClickedSearches + Conversions > 0 in the range: ItemGuid, title, content type, clicked searches, conversions, average click position (ClickPositionSum / ClickedSearches, null when 0), plus the total item count and the range's totals
And ties break by ItemGuid so paging is stable; avgPosition sorts ascending with nulls last, the others descending
And items no longer in the index are returned with title null and shown as "Not in this index" (never dropped, so totals reconcile)
And the query is one SQL aggregation over ItemDaily for the index and range (no per-item round trips); titles come from one SuiteItemLookup.Describe call for the page's GUIDs only
And the command requires Site Search → View and a valid index, like Report
```

## AC-2: Card on Search reports
```gherkin
Given the reports page with item data in the range
Then a "Top clicked items" Paper card (heading level 2) shows up to 10 rows: title (ellipsis; "Not in this index" Tag when missing), content type, Clicked searches (DataBar relative to the card's top value, number as text), Avg. position (1 decimal or "—"), Conversions
And the three numeric column headers sort the card (stable, keyboard-operable, aria-sort set)
And a "Show all" button opens the "All clicked items" side panel with the same columns and a RangeFooter (10/25/50, paging)
And closing the panel returns focus to "Show all"
And empty range → "No clicked items in this period" text in the card; failed request → the card keeps its last rows faded (Stale) with a Retry, like the other cards; loading → Spinner
```

## AC-3: Pin or hide through a new rule
```gherkin
Given a row with an item that is still in the index and a user with Manage rules
When they choose "Pin in a new rule" (or "Hide in a new rule")
Then rule create opens for the same index with that item pre-filled in Pinned items at position 1 (or in Hidden items), through the one-time handoff (target, index, exact path, expiry; consumed once; only filled when the list is empty)
And conditions are left for the marketer to choose (nothing is saved automatically; the form's existing validation applies)
And because a rule without conditions fires on every search (RuleEngine: Conditions.Count == 0 matches all), the rule form shows a visible warning in the Conditions section whenever the list is empty, on create and edit: "No conditions: this rule applies to every search." It is a polite, always-rendered notice (not an error, saving stays allowed) so a pin or hide made from the report is never silently site-wide <!-- audit-added -->
And without Manage rules, or for an item not in the index, the actions are disabled with a reason (aria and title, as in the query table)
```

## AC-4: No regressions

```gherkin
Then the existing Report/Queries/Insights commands, cards, query handoffs and rule/synonym create flows behave as before
And at ~670 and ~1270 px content width nothing overflows; rows stay one line (50 px)
And Debug + Release 0 warnings; full .NET suite, client tests and tsc pass; new public types in PublicAPI.Unshipped.txt
```
