<objective>
## Goal
Add three view components to the Widgets package that render a working, tracked search page with no client framework:
- `<vc:lucene-suite-search-box>` — a GET search form.
- `<vc:lucene-suite-results>` — hits (title, summary, link with `sr=`), result count, pagination, click beacons.
- `<vc:lucene-suite-facets>` — facet values as toggle links.

All components on a page share **one** search per request (one analytics row), driven entirely by the URL: `q`, `page`, `f.{dimension}`, `sid`, `seq`.

User decisions (2026-10-11): view components with overridable Razor views (06-03 Page Builder widgets wrap them); toggle-link facets (no JS); `sr=` always on result links; hit title/URL/summary chosen by field-name parameters (defaults `Title`, Kentico `Url`, none).

## Purpose
Core value: real Suite traffic. A site gets correct analytics (logical searches, sequences, clicks, conversion references) by dropping three tags on a page; no custom code.

## Output
- URL model + per-request search service + contact-group contexts.
- Three view components with default Razor views (overridable by path).
- Click-binding module `lucene-suite-results.js` (uses `lucene-suite.js`).
- .NET tests (URL model; rendered HTML via an in-process MVC host) + node test for the click payload.
</objective>

<acceptance_criteria>

## AC-1: URL model
```gherkin
Given SuiteSearchUrl.Parse(IQueryCollection) and its link builders
Then q (trimmed, ≤ 256 chars, longer → treated as invalid), page (1..⌈1000 / pageSize⌉, invalid → 1), f.{dimension}=value (repeatable; at most 10 dimensions × 20 values, each ≤ 256 chars; extras ignored), sid (non-empty GUID) and seq (1–10 000) are parsed without throwing for any input
And link builders produce: page links and facet-toggle links that keep q and the other filters and carry sid=<response SearchId>&seq=<current seq + 1>; the search-box form carries neither (a submit starts a new search)
And toggling a selected facet value removes it, an unselected one adds it, and any filter change resets page to 1
And all values are URL-encoded (round trip through Parse is lossless, including spaces, '&', '=', non-ASCII and dimension names with dots)
```

## AC-2: One search per request, correct analytics fields
```gherkin
Given several Lucene Suite components for the same index on one page
When the page renders
Then ISuiteSearchService.Search runs exactly once per index per request, with Query, Facets, Page, PageSize (SuiteWidgetsOptions.PageSize, default 10, 1–100), Contexts, TrackAnalytics = true
And with no valid sid: SearchId null (server mints), IsSubmit = true only when q is non-empty
And with a valid sid + seq: SearchId = sid, Sequence = seq, IsSubmit = false — but only when the navigation is same-origin (Sec-Fetch-Site same-origin, or the header is absent); a pasted/bookmarked/cross-site URL (none / cross-site / same-site) starts a new server-minted search so shared links don't collide with the original visitor's rows
And request errors (ArgumentException from the search, e.g. an unknown facet dimension or over-long value from a tampered URL) render the empty/invalid state, are logged at debug level, and never fail the page
<!-- audit-added -->
And an index name that does not exist is a developer error: SuitePageSearch checks it before searching and throws InvalidOperationException naming the index (loud in development, never shown as "no results")
And any other search failure (Lucene I/O, index rebuild, rules/synonyms outage beyond core fail-open) renders an "unavailable" state, logs an error (throttled, no query text) and never fails the page; OperationCanceledException from an aborted request propagates
And whenever a component runs a search, the response is marked uncacheable: Cache-Control "no-store" (when headers are not yet sent) and ASP.NET output caching storage disabled for the request (IOutputCacheFeature.Context.AllowCacheStorage = false) — cached HTML would replay sid/seq links to other visitors, skip analytics, and serve one contact's context-specific results to everyone
And the components render nothing searched when q is empty and no filters are set, unless SuiteWidgetsOptions.SearchOnEmptyQuery (default false) is true
```

## AC-3: Visitor contact groups as contexts
```gherkin
Given SuiteWidgetsOptions.ContactGroupContexts = true (default)
When there is a current contact (ContactManagementContext.GetCurrentContact(createAnonymous: false) — never creates one)
Then the code names of its contact groups (excluding recipient lists; at most 50, ≤ 100 chars) are sent as Contexts
And the membership lookup is cached per contact (5 minutes, cache dependency on contact group membership) so a results page costs at most one membership query per contact per 5 minutes
And with no current contact, the option off, or any lookup failure (logged, throttled), Contexts is empty and search continues
```

## AC-4: Default views
```gherkin
Given the default Razor views (overridable at Views/Shared/Components/LuceneSuite*/Default.cshtml in the host)
Then the search box is a labelled GET form (role="search") to a configurable action URL (default: current path) with input name "q"
And results render: a status line ("N results for “q”", or the empty/invalid state), an ordered list of hits starting at the absolute position, each with the title (field parameter, default "Title"; falls back to the URL), optional summary field, and — when the URL field (default Kentico "Url") has a value — a link whose href carries sr=<SuiteResultReference> appended correctly to any existing query/fragment, plus data attributes for the click beacon; hits without a URL render unlinked and untracked
And pagination is a nav (aria-label) with Previous/Next and aria-current on the current page, using AC-1 links, capped at the 1000-result window
<!-- audit-added -->
And hit hrefs are rendered only for a relative path ("/…" but not "//…") or an absolute http/https URL; any other value (javascript:, data:, protocol-relative, unparsable) renders the hit unlinked and untracked. sr= and click data attributes are added only when the link stays on the current site (relative, or absolute with the request's host); external links get neither, so search ids never leave the site
And pagination and facet toggle links carry rel="nofollow" (crawlers must not walk the facet × page combinations)
And a facet value selected in the URL but absent from the response's top values is still rendered (selected, count 0), so every active filter can be removed
And facets render one group per dimension (heading + list) of toggle links showing label, count and selected state (visually and as text for screen readers, aria-current or visually hidden "selected")
And all output is HTML-encoded (stored field values, query text, facet labels); no inline script or style (CSP-safe)
And the results view includes <script type="module" src="_content/XperienceCommunity.Lucene.Suite.Widgets/lucene-suite-results.js" asp-append-version> only when MapLuceneSuiteEvents was called (the events URL is known)
```

## AC-5: Click beacons
```gherkin
Given lucene-suite-results.js on a results page
When a visitor activates a result link (click, middle-click/auxclick, keyboard Enter)
Then it calls sendClick(eventsUrl, { searchId, sequence, itemGuid, position }) from the link's data attributes, once per activation, without preventing navigation
And a link with missing/invalid data attributes sends nothing
And clickPayload(element) (exported, pure) is node-tested for valid and invalid attribute sets
```
