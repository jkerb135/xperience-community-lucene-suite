<objective>
## Goal
Make the search components available to marketers as Page Builder widgets and prove the whole v0.1 loop on the test host:
- Three widgets — **Lucene Suite search box**, **Lucene Suite search results**, **Lucene Suite search filters** — registered by the Widgets package, wrapping the 06-02 view components (same overridable views).
- Preview / Page Builder edit mode never records analytics or tracked links, and editors see a placeholder instead of an empty widget.
- Facets get dimension display labels (widget property + view component parameter).
- CommunityProjects: wire the package and keep a **Search** landing page with the three widgets; an end-to-end run records searches, continuations and a click in `comm_projects`.

User decisions (2026-10-11): search box targets the results page via a **page selector** (empty = current page); **keep** a permanent Search page on the host (ongoing traffic for v0.2); facet labels as a **widget property** ("Dimension = Label" per line). Checkpoint review goes to `.paul/APPROVAL-CHECKS.md` (no blocking checkpoint).

<acceptance_criteria>

## AC-1: Widgets registered and configurable
```gherkin
Given the Widgets package is referenced by a Page Builder site
Then three widgets are registered with stable identifiers (XperienceCommunity.LuceneSuite.SearchBox / .SearchResults / .SearchFilters), names, descriptions, icons and AllowCache = false
And their properties are:
  - Search box: Results page (page selector, max 1; empty = current page), Label (default "Search"), Placeholder
  - Search results: Index (drop-down of Kentico Lucene index names, required), Title field ("Title"), URL field ("Url"), Summary field (optional)
  - Search filters: Index (same drop-down, required), Dimension labels (text area, "Dimension = Label" per line)
And each widget renders the same default view (and model) as its 06-02 view component, so a site override of Views/Shared/Components/LuceneSuite*/Default.cshtml applies to both
And the selected results page resolves to its live URL in the page's language at render time; a missing/deleted page falls back to the current page and logs a throttled warning
And a widget whose Index is empty or no longer exists renders an editor-visible message in edit mode and nothing on the live site (logged) — never an error page
<!-- audit-added -->
And the Widgets assembly carries [assembly: AssemblyDiscoverable] (Kentico only scans discoverable assemblies for RegisterWidget; without it the widgets silently never appear)
```

## AC-2: Preview and edit mode are never tracked
```gherkin
Given a page rendered in Kentico preview or Page Builder edit mode
When any Lucene Suite component searches
Then the request uses TrackAnalytics = false and Contexts empty (no contact lookup)
And result links carry no sr= and no click data, and the beacon script is not rendered
And in edit mode, a results/filters widget with nothing to search shows a short placeholder ("Search results appear here when a visitor searches") instead of rendering nothing
<!-- audit-added -->
And preview detection fails closed: if the preview/edit state cannot be read (exception), the request is treated as preview (untracked) and a throttled warning is logged
And in edit mode the search box form is inert (controls inside a disabled fieldset), so editors cannot navigate the Page Builder frame away by submitting it
```

## AC-3: Facet dimension labels
```gherkin
Given labels "ContentType = Content type" (one per line; blank lines and lines without "=" ignored; first "=" splits; trimmed; dimension match ordinal)
Then the facet group heading shows "Content type" while links keep the raw dimension name
And unlisted dimensions show their raw name
And the label map is exposed on the view model so overridden views can use it
```

## AC-4: Contact-group query proven on a database
```gherkin
Given the disposable comm_projects_test database (LUCENESUITE_TEST_CONNECTIONSTRING)
When a contact belongs to a contact group, a recipient list and nothing else
Then SuiteContactGroupContexts' query returns only the contact group's code name
And the test removes everything it created
```

## AC-5: Host end-to-end with real traffic
```gherkin
Given CommunityProjects references the Widgets package, calls AddLuceneSuiteWidgets and MapLuceneSuiteEvents, and has a permanent "Search" landing page (25/75 section: filters in the side panel, results in the main zone, a search box above)
When a visitor searches "coffee" in the browser, opens page 2, toggles a facet, and clicks a result
Then comm_projects receives: one SearchEvent per request with the same SearchId and sequences 1, 2, 3 (submit only on the first), and one SearchInteraction click with the clicked position and the sequence of the response that listed it
And the result page URL carries sr= that SuiteResultReference parses back to those values
And the response has Cache-Control: no-store; the events POST returns 202
And opening the same page in Page Builder edit mode or preview records nothing new
And the host log shows no new errors from the Suite
```
