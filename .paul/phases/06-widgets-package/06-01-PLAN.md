<objective>
## Goal
Create the optional `XperienceCommunity.Lucene.Suite.Widgets` package with its live-site plumbing:
- `AddLuceneSuiteWidgets()` + `MapLuceneSuiteEvents()`: a rate-limited POST endpoint that records clicks and conversions through `ISearchInteractionLogger`, and a GET endpoint returning the client settings (the server's merge/attribution values).
- `SuiteResultReference`: format/parse the `sr=<searchId>.<sequence>.<position>` link parameter for conversions on later pages.
- `lucene-suite.js`: a dependency-free ES module shipped as a static web asset, implementing the full analytics client contract (searchId minter, typo/continuation rules, click/conversion beacons), tested against `docs/analytics-test-vectors.json`.

User decisions (2026-10-11): server-rendered widgets; Search box + Results + Facets as separate widgets; visitor contact groups as contexts (configurable); three plans (06-01 package + endpoint + JS client, 06-02 tag helpers + server rendering, 06-03 Page Builder widgets + host wiring); full contract JS client now (reusable by custom UIs even though server-rendered widgets continue searches through server-rendered links).

## Purpose
Core value: real Suite traffic and measurement. The endpoint is the only way clicks/conversions reach analytics from a browser; the JS client lets custom search UIs follow the contract exactly.

## Output
- New Razor class library project in the solution (net10.0, own package metadata).
- Endpoint, settings, sr= helper, DI extension.
- JS client + node tests on the shared vectors.
- .NET endpoint tests (in-process host).
- Contract doc updated to point at the shipped client.
</objective>

## AC-1: Package skeleton
```gherkin
Given the solution
Then src/XperienceCommunity.Lucene.Suite.Widgets is a Razor class library (Microsoft.NET.Sdk.Razor, net10.0, nullable, warnings as errors, XML docs) referencing the core project only
And it packs as XperienceCommunity.Lucene.Suite.Widgets with the same license/metadata as the core package and ships wwwroot/lucene-suite.js as a static web asset (_content/XperienceCommunity.Lucene.Suite.Widgets/lucene-suite.js)
And AddLuceneSuiteWidgets(this IServiceCollection, Action<SuiteWidgetsOptions>?) registers its options and its own events rate limiter; it requires AddLuceneSuite (throws a clear InvalidOperationException at startup otherwise)
<!-- audit-added -->
And the package never mutates the host's RateLimiterOptions (no AddRateLimiter, no global RejectionStatusCode) and does not depend on the host calling UseRateLimiter: the events endpoint owns a singleton PartitionedRateLimiter and acquires a lease in its handler
```

## AC-2: Events endpoint
```gherkin
Given app.MapLuceneSuiteEvents(pattern = "/lucenesuite/events") and app.UseRateLimiter()
When a browser POSTs JSON { type: "click" | "conversion", searchId, sequence, itemGuid, position?, eventId }
Then it calls ISearchInteractionLogger.LogClick / LogConversion and returns 202 Accepted with no body
And invalid input returns 400 without details beyond a short message: unknown type, unparsable JSON, missing/empty GUIDs, ArgumentException from the logger (sequence < 1, position out of range)
And bodies over 1 KB are rejected (413), only POST is mapped, and both application/json and text/plain bodies are accepted (sendBeacon with a string sends text/plain)
And requests are rate-limited per client IP (as resolved by ASP.NET Core, so forwarded headers apply when the site configures them) with a fixed window — default 60 events/minute, configurable via SuiteWidgetsOptions — returning 429 when exceeded; the IP is never stored
<!-- audit-added -->
And EventsPerMinute = 0 disables the limiter (for sites behind a proxy/CDN that rate-limits upstream); the first rejection per minute logs a throttled warning that names forwarded-headers configuration, because behind an unconfigured proxy every visitor shares one IP
And the body limit is enforced while reading (at most 1 024 bytes are buffered, chunked bodies included), not only from Content-Length
And eventId is optional: when missing the logger mints one (a retried beacon then counts twice, as the contract states)
And the endpoint never echoes input and sets Cache-Control: no-store
```

## AC-3: Client settings endpoint
```gherkin
Given GET {pattern}/settings
Then it returns { textChangeTimeoutMs, typoOneEditMinLength, typoTwoEditMinLength, deepBackspaceRatio, attributionWindowMs, eventsUrl } from the server's validated SuiteSearchOptions (same names as the vectors' settings)
And it is cacheable for 5 minutes (public, max-age=300) and not rate-limited
```

## AC-4: Result reference (sr=)
```gherkin
Given SuiteResultReference
Then Format(searchId, sequence, position) returns "<guid N format>.<sequence>.<position>"
And TryParse(string?) returns false (never throws) for null, wrong part count, non-GUID or empty GUID, sequence < 1, position outside 1–1000, or input longer than 64 characters
And a round trip returns the same values
```

## AC-5: JS client implements the contract
```gherkin
Given wwwroot/lucene-suite.js (ES module, no dependencies, no build step)
Then it exports createSearchTracker(settings) with beforeSend(input, isSubmit, now) → { searchId, sequence, isSubmit } following contract §2 exactly (norm, continuation, OSA typo distance, deep backspace, page/filter never time out, submit rules)
And newGuid() uses crypto.getRandomValues (16 bytes, RFC 4122 v4 layout)
And sendClick / sendConversion(eventsUrl, { searchId, sequence, itemGuid, position, eventId? }) use navigator.sendBeacon with a fetch(keepalive) fallback, minting eventId once per event
And loadSettings(settingsUrl) fetches the server settings
And formatResultReference / parseResultReference mirror SuiteResultReference
And node tests run every minting case in docs/analytics-test-vectors.json (search ordinal + seq per step, with per-case setting overrides) and pass; click steps check that the click carries the seq of the response it refers to
And state lives only in the tracker instance (no cookie, no localStorage)
```
